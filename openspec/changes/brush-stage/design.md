## Context
- `brush-items`: the item, its strokes (kind, `radius_m`, `strength_m`, `target_m`, points), caps, the hash. ADR 0066: a stage reads the base only as a height field at points; a layer is a stage over the layers below it. GEN-026/028/029: the stamp stage, the line stage, the region mask.

## Decisions
1. **Profile.** The distance `d` from the point to the stroke's polyline (the great-circle arcs, `polyline_angle`; a one-point stroke is a dab: the angle to the point) gives `x = d * R / radius_m` and the weight `w(x) = (1 - x^2)^2` for `x < 1`, else 0 (the ridge profile, so a stroke is smooth to the second order at its edge). Overlapping parts of one stroke do not add (the distance is a minimum).
2. **Strokes of an item apply in file order** to the running height `h` (the stage input plus what earlier items and earlier strokes added): raise `h += s * w`, lower `h -= s * w`, flatten `h += w * clamp(target - h, -s, s)`, smooth `h += w * clamp(m - b, -s, s)` where `b` is the stage input at the point and `m` the mean of the stage input at eight points on the circle of angular radius `radius_m / (2 R)` round it (bearings 0, 45, ... 315 degrees from the local east axis; `libm` sin and cos). Every stroke changes the height by at most `s * w` (`s` the strength), so an item changes it by at most the sum of its strengths, which `max_delta_m` bounds (WDEF-013).
3. **Smooth sees the stage input, not the layer's own earlier edits.** `b` and `m` come from the base below the layer, read through `base_at`; a smooth of a hill of the same layer smooths the ground under the hill, not the hill. The editor puts brush items in a layer above the one they should smooth (default layer `brush`, which stacks above the named layers of ADR 0007). Rejected: reading the running height at the ring (an evaluation of every earlier item at eight points, recursively).
4. **A function of the direction alone.** The ring is built from the point's own direction, so two tiles that share a point compute the same height there (no tile seam) and the result does not depend on the thread count (CON-14).
5. **The region mask (GEN-029)** cuts a brush like any item of its layer (the height there is the base's).
6. **Bounds (GEN-026).** `delta_range` of a brush item at a cap: the sum over its strokes of a range from `w(x_near)` and `w(x_far)` where the nearest and the farthest distance of the cap from the stroke's polyline give `x_near` and `x_far`: raise `[s w(x_far), s w(x_near)]` (low end 0 when `x_far >= 1`), lower the negative of it, flatten and smooth `[-s w(x_near), s w(x_near)]`; widened as the lines' are. The item adds to the sum like a radial stamp.
7. **Cost.** A sample tests each stroke's reach disc (anchor distance against `reach_m`) first, then the stroke's polyline distance; the eight ring reads happen only inside a smooth stroke. An item of 64 strokes costs a handful of distance tests per sample away from them.
8. **Preview.** `preview_delta` skips brushes, as lines (a brush shows when its exact tiles arrive).

## Risks
- A smooth stroke costs nine base reads per sample inside it; on an eroded bake each read is a bilinear lookup plus noise. The edit-latency scene gets a brush case later if the number matters.
- `delta_range` for a flatten and a smooth is symmetric and does not use the target: the bounds are wider than needed, never too narrow.
