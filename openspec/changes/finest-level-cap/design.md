## Decisions

- **One source of truth.** `LodParams::max_level`. `production_finest_level(cells)` is the production value and the only place the relation lives: `2^level * cells = 2^27` (a face edge of 134 million cells, 7.46 cm per cell at Earth's radius), so `27 - ceil(log2(cells))`; a tile size that is not a power of two rounds the spacing up (coarser), never down. Tests and tools that need another cap (the SPIKE-07 comparisons at 26, a steep-field fixture at 9) set `max_level` explicitly; `--finest-level N` does it on the command line.
- **Format per finest level: the key identifies it.** The CON-13 guard falls back to the vertex format for a finest tile with more than 65.535 m of relief; "finest" is the LOD cap. A resident tile is reused by its mesh key, so the key has to say what the decision depended on: the tile, the field, and whether the tile is at or above the cap. `finest_class_key(base, id, cap)` rehashes the base key for a finest tile and leaves other tiles' keys alone (the cap's value is not part of the key: equal classes share keys, and relief is a function of the tile). Alternatives rejected: re-deciding and re-uploading on a cap change (needs a mechanism in the streamer and the pool, for a change that does not happen inside a session), and a per-tile format flag outside the key (the plan could not see it). A `--pipelined` script still refuses requests that change the cap or the cells: the renderer's pools and the streamer's tile source are built for the first request's values; what changed is that a tile built for another class can no longer be taken for the planned one.
- **MESH_VERSION 6.** Keys of finest tiles change, so the version changes (GEN-010: a key composition that gains an input bumps the version). Consequences: persistent mesh keys (kind mesh, the cache crate's known answer) change; no store holds meshes or compact tiles (the pack stores height tiles, unchanged); repro bundles of mesh version 5 are refused with the versions named; vertex mesh content hashes are unchanged.
- **Pins and snapshots.** The standard views are planned at the production cap; only ground-1m reaches 22. The level-26 pin of that view is kept as `REFERENCE_L26_GROUND_1M` (reference field and default world) and the level-26 headroom pins of ground-1m as `PINS_L26_GROUND_1M`, so SPIKE-07 stays reproducible. `lod_views.txt` changes in its ground-1m line only; `terrain_plans.txt` and `terrain_plan_orbit.txt` change in hashes and mesh keys only (the version).
- **Goldens.** Only `terrain_ground1m_depth` moves (149 px WARP, 157 px RTX, delta 3), because the golden test now plans at the production cap of cells 16 (23). The local WARP driver (10.0.26100.9711) differs from the recorded one (33438), so its candidate escalates by rule; the classification uses the CI candidates (WARP, llvmpipe) and the local RTX one.
