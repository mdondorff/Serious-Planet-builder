## Why

ADR 0026 point 5 was left open until the first regional field reads the bake, and the store review (m3-global-store) found a layout gap: the bake's stage key covers `res`, block keys cover `B`, so one bake could be stored twice in different layouts. ADR 0027 (proposed) decides both; this change implements it before task 4's first regional field.

## What Changes

- Canonical layout (ADR 0027 point 1): `GlobalWorld::layout(res)` gives `(level, cells)` with `B = min(res, limit)` (limit 1024, a store policy settable only through `with_block_limit` for tests); `build_global(dir, world, res, threads, max_pack)` takes `res`, not `(level, cells)`; `block_record` refuses another layout; `verify_global` reports a block of another layout as unreadable. CLI: `--global-dir DIR --global-res N` replaces `--global-level` and `--global-cells`.
- Reader (ADR 0027 points 2 to 5): `generators::global::read_lattice` and `read_tile_sample` read the bake at integer lattice positions with the edge-symmetric blend `a (1 - w) + b w` (a neighbour with weight 0 is not read), halo hold beyond a face edge (positions from `-N` to `2N` accepted, anything farther an error), `LatticeSource` (`GridSource` for memory), `ReadError`, `READER_VERSION` 1.
- `planet_cache::global_store::StoreSource`: the stored bake as a lattice source (finds each block through the layout, decodes it once, keeps 16, names a missing or damaged block with its key).
- GEN-015 added; STRM-012 modified (layout, source, CLI). Tests: `generators/tests/global_reader.rs` (8: lattice points at every target resolution, equal values on shared face edges between bake samples, partition invariance, blend and convergence, halo and errors, a synthetic-lattice arithmetic pin, zero-weight neighbours and signed zero, pinned known answers) and store tests (the stored bake reads like the in-memory one at every vertex and between them, missing block error, canonical layout, refusals).
- Decisions for the architect in ADR 0027 (proposed): canonical layout, integer positions, edge-symmetric blend, halo hold (a limitation across face edges for stencils), land by interpolated continentalness, one upstream key.
- Review fixes (numerics): zero-weight neighbours unread (a lattice point is its own sample, signed zero kept), range check on positions, ADR 0022 halo width, a synthetic-lattice arithmetic test independent of the field, `StoreSource` cache is LRU and does not hold its lock during decode, `with_block_limit` is test support (doc-hidden; the limit is recorded nowhere, a store keeps one for good), layout errors name the finest grid, ADR 0027 text corrected (trait name, zero sign, halo width, what the known answers cover).
- Not tested here: the rule that land after interpolation is decided by interpolated continentalness (ADR 0027 point 5) binds consumers; it gets its test with the first regional field. `with_block_limit` stays `pub` (doc-hidden) for tests; ADR 0027 point 1 means the CLI and `build_global` offer no way to choose a layout.
- Not here: the first regional field that uses the reader (task 4), a reader that crosses a face edge for halos.
