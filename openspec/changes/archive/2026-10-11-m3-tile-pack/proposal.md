## Why

M3 queue item 5, second part, ADR 0019 (accepted by the owner, 2026-10-11): the disk tier between the RAM LRU and the generators. It must serve a tile quickly, never block a frame, survive a crash without corrupting later reads, and let the editor and the headless `generate` mode share one store.

## What Changes

- `planet_cache::hilbert`: the standard 2D Hilbert curve (`xy_to_d`, `d_to_xy`) and the 11-byte `sort_key(kind, tile)`.
- `planet_cache::crc32c`: CRC-32C in-tree (table, no unsafe, no dependency), checked against the published values.
- `planet_cache::pack` (pack format version 2): `Record` and its wire format (a CRC over the record header as well as the payload), `PackWriter` (one advisory `File::try_lock` per directory, torn-tail truncation, atomic index writes, rollover at a size limit, a failed append undone), `TileStore` (reads every pack of a directory, rebuilds a missing, stale or hostile index in memory, `get` by kind, tile and key, newest wins, packs that are unreadable, still being created or of an older hash version skipped and listed in `problems()`), `PackError` with actionable messages (corruption names file, offset and key; a locked directory names the holder).
- Modified: STRM-008 added (tier A). Tests: six in `hilbert_crc.rs` (the curve matches the standard 4x4 listing and ends at the standard corner up to order 31, bijection, consecutive cells adjacent, children contiguous, bounded neighbour distance; CRC published values) and twenty in `pack.rs` (including damage that skips instead of cutting, a damaged header leaving a pack untouched, zero-filled tails, hostile index entries and counts, partial and foreign packs, hash version bumps, non-canonical names, sequence exhaustion, and a lock released by a really killed child process).
- Review fixes (verifier, spec-guardian, numerics-reviewer): damage handling no longer cuts good records, header CRC, index entries bounds-checked, streaming CRC, a hash version bump invalidates instead of failing the store, partial packs do not fail readers, directory-level writer lock, failed appends undone, checked arithmetic, canonical names, `rust-version` 1.89 in the workspace.
- Proposed ADR 0024 records what the implementation had to settle in ADR 0019: the record carries its tile id and a header CRC, the header and index layouts (40-byte entries), staleness, hostile-index and damage rules, hash version and body handling, duplicates, the size limit, the directory lock and that the Windows lock is mandatory so the holder note is a separate file.
- Not here: compression (byte shuffle plus LZ4), compaction and the size cap, `cargo xtask cache-verify`, wiring the store into the streamer and the `generate` CLI.
