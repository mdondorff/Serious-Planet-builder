## Decisions

- **Atlas count and size.** Atlases are 4096 x 4096 `Rgba16Uint` textures (128 MiB), allocated on first use. At cells 32 a block holds 124 x 124 = 15,376 slots; the mid share (2 GiB less the 0.125 GiB fixed reserve) is exactly 15 atlases = 230,640 slots, the high share 23 atlases = 353,648 slots (ADR 0033's figures, pinned in `compact_pool.rs`). One big texture array was rejected: it cannot grow, so the whole 1.9 GiB would be one allocation.
- **Binding scheme (the open point of ADR 0033 point 3).** No binding arrays and no texture index per draw. A draw names its atlas by being in a run of that atlas: the run's bind group (group 2) holds the atlas texture. It names its slot through the node: the per-frame *tile reference* (16 B per node: texel origin x and y, slot index) is read with the instance index, which is `first_instance` = the node index, exactly as the node record is; the slot index selects the 128 B record (control points, height range, skirt depth, flip) in one persistent storage buffer (group 1, one record per main-pool slot, allocated with the renderer). The compact pipeline's group 0 is the product's (globals, node records), so the fragment stage and the node record are shared. This needs no adapter feature beyond what REND-015 already uses and runs identically on WARP and the RTX. Cost: one bind-group change per atlas boundary along the plan (at most 15 at the mid share, one or two for a settled view because slots are handed out lowest first).
- **Two formats in one frame.** The draw list's runs carry the buffer kind; a run of `DrawBuffer::Atlas` binds the compact pipeline, any other run the vertex pipeline. The plan's order is kept, so depth ties resolve as in the per-draw loop and the two paths are identical. A plan with fallback or coarse tiles in between splits runs; they are few (levels 0-2 and steep finest tiles).
- **Fallback tiles (CON-13) and the manager.** The residency manager reserves a main slot when it dispatches a tile, before the tile exists; whether a finest tile falls back is known only after it is built. The renderer therefore keeps fallback tiles in its own region of the vertex pool (the top 256 of the 512 slots; the manager's vertex pool is the bottom 256, levels 0-2 need at most 126) with its own free list and frames-in-flight retirement, and the main slot the manager gave stays empty while the tile lives (8.7 KB of atlas, once per fallback tile; zero fallbacks on the standard views). A fallback beyond the region is refused with `PoolFull` and the tile id rather than breaching the share.
- **Accounting.** `PoolConfig::allocated_bytes` = atlases (the texture size, not slots x slot bytes) + vertex pool + index buffer + node records + the slot-record buffer (`main_slots` x 128 B, 29.5 MB mid / 45.3 MB high, inside the 0.125 GiB reserve with the 27.5 MB vertex pool and 16.8 MB node records). The vertex-format configurations have zeros for the new fields and unchanged numbers.
- **Shader.** The compact vertex stage is the spike's with 16-bit normals (`unpack2x16snorm`), control points loaded once per vertex from the record, storage-buffer records instead of a 144 B uniform per node, `node_index` passed to the fragment stage. The vertex stage is spliced into the product shader's text at build time for the tile size (a WGSL constant), so no planet-scale value can enter (REND-005 scan covers it).
- **Compact pools start at cells 32.** The record buffer (128 B x slots of the main pool) counts with the fixed items, and at cells 16 the mid share would need 110 MB of records beside the vertex pool and node records, over the 0.125 GiB reserve; `fit_share_with` refuses it with the numbers (tested). Smaller tiles use the vertex format. Cells 64 fits.
- **Open for part 3.** (a) The format decision depends on the view's finest level but the key does not; a consumer that reuses a resident tile under another `max_level` must re-check `CompactTile::allowed_at_finest_level` (part 3 builds tiles with the plan's `max_level` and the app has one). (b) The wiring must handle `PoolFull { Vertex }` from the fallback region.
