## Design

**The field and where it rides.** The climate is a field (ADR 0035 point 1: generated, stored, keyed, read by the renderer): 81 texels x (temperature, precipitation) as f16, read with `read_tile_sample(src, tile, 8, a, b)`: the 9 x 9 points sit on the tile square including the border, so neighbouring tiles agree on shared texels (the reader is face-edge symmetric and no position needs the halo rule). The f16 rounding is part of the definition (the field *is* the rounded value), so the CPU is canonical and the GPU decode is exact; the quantisation against the bake (2^-11 of the value) is declared in GEN-021. ADR 0039 asks for "abs 0.01 degrees and 0.1 mm": f16 cannot hold 0.01 degrees above 16 degrees or 0.1 mm above 128 mm, so the bound is recorded as zero CPU/GPU difference plus a declared quantisation (reported as an amendment point).

**Storage without new bytes in the production format.** The compact texel's fourth channel was reserved (zero). The 162 f16 values go into the first 162 texels' fourth channel (temperature `k`, precipitation `81 + k`), so the atlas, the pool slots, the 8,840 B tile and ADR 0033's compact slot counts are unchanged, the persistent payload already stores all four channels, and no new buffer, binding or upload exists. The cost is that compact tiles need at least 16 cells (162 texels); the CLI refuses `--cells` below 16 with the compact format, naming the minimum. The vertex format (levels 0-2, CON-13 fallbacks and the `--tile-format vertex` reference) has no spare bits: the tile carries the 324-byte block (payload version 2) and the GPU vertex gets two f16 (the stored texture sampled at the vertex, 48 B stride instead of 44). The fragment stage then needs no uv and no extra binding for it; for compact tiles the vertex stage outputs the tile coordinates and the fragment stage reads eight texels.

**The slope input without planet-sized values.** Slope = the angle between the shading normal and up. Up at a fragment is `normalize(up0 + local / R)` where `up0` and `1 / R` are in the node record (decided in f64, rounded once) and `local` is the tile-local position: exactly the radial direction, formed from small numbers (CON-11 v1.4). Bound and stability are tested through the shader's own `up_at` (tier B probe).

**Albedo.** One pure function (`AlbedoParams::albedo`, `terrain_radiance`) in `frame::look::shading`, evaluated in f64 as the reference and in f32 in WGSL with the same operations (`smoothstep`, `mix`). The table is look data (ten `vec4` in the globals), the thresholds are ordered pairs validated so every smoothstep has an interval. Beach and seabed are measured from the plan's water level W (a constant 0 until the water-level field of item 6), never from a hard-coded sea level.

**Look schema 2.** Tables `sun` and `albedo` added; identity step 1 to 2; the version 1 fixture is kept and loads through the production chain; a version 2 fixture is added. The canonical text writes every key of both tables.

**Keys and the pack.** `mesh_key_chain` gains the climate version word (`HeightField::climate_version_word`: climate, reader and bake versions for a field over a bake; climate and analytic versions otherwise) and the persistent mesh key gains the same as output parameter 6. MESH_VERSION 7 changes every key, so stale tiles are unreachable; the pack codec's version 2 refuses old payloads so a stale record under a current key could never be misread (it cannot occur, but the refusal is tested). The vertex content hash does not cover the climate, so the committed vertex mesh known answers are unchanged (evidence that the vertex geometry did not move); the compact content hash covers the fourth channel and is re-recorded.

**Pins moved by the bytes.** Vertex-format slots (34,304 / 52,480), the 17-slot upload, 516 frames of a ground-1m fill, 228 B per node and frame, plan counts 1,221 x 48 B per vertex tile, the managed loop digests (they hash uploaded bytes). Streamer digests, compact pins and every debug golden are unchanged.
