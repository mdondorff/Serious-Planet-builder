## Why

M4 item 7, frame pipelining (optimization review item A, ADR 0032 point 5 and the planner's decision of 2026-10-15 on cold altitude plans, option a). Today every frame loop plans on the frame thread and waits for the GPU of the frame it just submitted (`render` polls the device to completion). A cold plan costs 25-30 ms with the reference field, 184 ms at ground-1m and 3-4 s at orbit and 2000 km with the eroded field over the 16384 store (7a/7b), so a teleport freezes the loop for as long as the plan takes, and a plan of 6-7 ms, an encode of 6 ms and a GPU time of 4 ms run in a row at ground-1m instead of overlapping. ADR 0032 decided: no frame waits for a plan; frame 0 after a jump draws a cover plan (the deepest resident ancestors, no field evaluation) and the full plan arrives from a worker.

## What Changes

- frame, `pipeline` module (GPU-free, CON-03): `FramesInFlight` (the bound `MAX_FRAMES_IN_FLIGHT` = 2, counted, the slot retire rule), `PlanWorker` (plans on a spawner, one at a time, the newest request replaces one that waits; every plan is a pure function of its request, so thread count and timing change nothing), `draw_plan` (the plan a frame draws: the newest usable completed plan rebased to the frame's camera with each non-resident node replaced by its deepest resident ancestor, or the cover), `plan_usable` (the stale-plan rule), `PlanPipeline` (the per-frame glue), `FrameColumns` (plan, scheduler, upload, record, GPU and wall time as separate columns, names fixed).
- frame, `lod::cover_selection`: the cover of a view as a pure function of the camera, the LOD parameters and the resident set (their origins); it evaluates no height field.
- frame, `terrain::plan_terrain_threaded`: origin heights of the nodes a cache has not seen are evaluated on worker threads (pure per tile, so identical for any thread count); the warm `SelectionCache` is unchanged.
- render: `TerrainRenderer::submit` (no wait), `retired_frames`, `wait_oldest` (the only wait: when the bound is reached), `with_frames_in_flight` (pools retire a released slot after the bound). `render` keeps its synchronous contract.
- app: `test-render --scene terrain --pipelined [--then SCRIPT] [--out-dir DIR]` runs the view through the pipelined loop (plans on a worker, streamer workers, renderer submits without waiting); the synchronous path stays the reference. `--out-dir` writes `pipelined.txt`, one line per frame drawn with the time columns.
- streaming-cache spec: STRM-002 gains *Teleport* and *Mouse look* scenarios (ADR 0032), STRM-016 (frame pipelining) added; testing spec: TEST-012 reports the columns.

Not in this change: wiring `ResidencyManager`/`Wants` (scheduler classes) into the loop (the loop still uses the bare `Streamer::begin_frame` with the draw set; the manager needs the residency set R from the worker and slot placement from the streamer, a change of its own), the perf scenes for dive, teleport and look (the architect measures), indirect multi-draw, the upload cap, GPU timestamps for submitted frames (a submitted frame has no GPU time; the GPU column is empty until the perf scenes drain a frame on purpose).

No golden, pinned count or MESH_VERSION changes.
