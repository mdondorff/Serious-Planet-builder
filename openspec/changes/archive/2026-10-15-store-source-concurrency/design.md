## Decisions

- Hot path: a thread-local memo of one `(source id, epoch, block)` entry. A hit reads the thread's own `Arc` without touching shared memory except one relaxed load of the eviction epoch. A lattice read of a tile stays in one or two blocks, so the memo serves almost every read. Alternatives rejected: `RwLock` shards (every read still does an atomic read-modify-write on the lock word of the block everyone is reading), a `ArcSwap` slot table (a new dependency, same memory-reclamation story as the epoch).
- Shared level: `Mutex<Lru>` keyed by block tile, touched only on a memo miss. Entries are `Arc<Slot>` with a `OnceLock` result, so concurrent threads wanting the same absent block wait for one decode (no duplicate 33 ms decodes). The map lock is not held while decoding. An error is returned to every waiter but the slot is removed, so the next read retries.
- Budget in bytes (`16 (cells + 1)^2` per block), at least one block, default 512 MiB (31 blocks of 1024 cells; 16 before). The eviction epoch makes every thread drop its pinned block at its next read after an eviction, so blocks alive are at most the budget plus the block each thread is reading plus blocks in decode.
- Results do not depend on the cache or the thread count: a block is a pure function of the stored record; every read returns the same bits whichever level served it (tests: 1, 4 and 20 threads, in-memory comparison).
- CRC-32C slicing-by-8 keeps the table-driven definition (no unsafe, no dependency, CPU feature independent) and is checked against the bytewise reference.
- Positional reads (`seek_read` on Windows, `read_exact_at` on Unix) replace seek-then-read under a mutex; the pack file is only read after open.
- Memory beyond the budget: each thread pins the block it read last, so with T reading threads the bound is the budget plus T blocks (20 threads of 1024-cell blocks: about 336 MB on top of 512 MiB). ADR 0033's 0.5 GB share for bake blocks should count the pins when the owner accepts it. A pin outlives its source until the thread reads again or exits.
- A tight budget can evict a block while it is being decoded; the next reader then decodes it again. A thread reading alternately across a block border misses its pin each time and takes the shared mutex (rare: a tile touches mostly one block, measured rate 83-98 % of in-memory).
- The pack's `dropped` list stays a mutex: it is taken once per block fetch, never per lattice read.
