## Design

**Where it lives (CON-02, CON-03).** `planet_frame::look` already holds the lit path's GPU-free maths; the file layer is its submodule `look::file` (schema, parse, validate, migrate, canonical write, defaults). `frame` is above `world-def` in the layering, so it may name `BodyId`; the look file addresses bodies by the same id as the definition, and nothing in `world-def` names the look. File reading is in `app::lookload` (the apps already read files; `frame` stays pure text in, data out).

**Outside the hash by construction.** The look file is never an argument of `WorldDefinition`, `GenContext`, `World` or any key function, and `world-def`, `generators`, `cache` and `streaming` sit below `frame`, so they cannot name it. The independence test takes the definition hash (against its recorded known answer), base hash, canonical text, node-set id, store parameters, height keys and read set, loads looks (default and one with every value changed for three bodies) and compares. A `kind = "look"` marker makes the two TOML files non-interchangeable: the definition loader rejects a string value, the look loader requires the marker.

**What is look data (ADR 0042 point 6, ADR 0048 point 2, ADR 0041).** In this change: the scene-unit scale (`units.solar_illuminance_lux`), the exposure range and speeds, the histogram axis and band, the tone curve. Not look data: the bin count (64: the shaders' structure), the EV conventions `1.2` and `8` (the formula of saturation-based exposure), `HDR_CLAMP` (an f16 safety limit), and anything a generator reads. Liquid kinds are world data (M5 constraint 3; ADR 0041): only a liquid's appearance may come to the look file in item 7, keyed by the kind id the definition names. The sun direction and albedo of item 4: the albedo tables are look data (ADR 0042 point 6), the sun's position is a function of time and body and a plan field, not a look value.

**Schema.** Every key is optional (a missing key is the Earth default, so a body without an entry is the default as a whole and adding an optional key or table later needs no migration); unknown keys are errors (a typo must not fall back silently); numbers are `f64` as read (so the text round-trips bit for bit) and rounded once to `f32` where a shader takes them. Validation is one function per table, shared by the file reader, `LookFile::set_body` and `LitPlan::validate`, so a plan from a repro bundle is refused with the same words as a file. The ranges are limits of sense (a sun between 1 lux and 1e7 lux covers every body of a solar system; EVs within -20..40), not tuning advice.

**Migrations.** Same engine shape as `toml_io::parse_with`: the file's version, refuse newer, apply `from -> from + 1` steps, set the version after each, then read the current layout. Version 1 is the first layout, so `MIGRATIONS` is empty and CON-10's "fixture of an older version" is met the way WDEF-002 meets it until a second layout exists: the version 1 fixture loads through the production chain, and a synthetic three-version chain (`lo`/`hi` to `min`/`max` to `min_ev100`/`max_ev100`) is migrated, compared with the current layout and written back to identical canonical text; failure, gap and duplicate-step paths are tested. A test pins `MIGRATIONS.len() == SCHEMA_VERSION - 1` so a version bump without a step fails.

**The plan and the shaders.** `LitPlan` gains `units` and `histogram`. Its text form appends ` units <f64 bits> hist <4 f64 bits>` only when either differs from the Earth value, and the reader accepts both forms, so text made before this change reads as the default and default plans write what they always wrote. The renderer's pre-exposure factor is `pre_exposure_factor_with(&plan.units, pre)` rounded once to f32. The histogram and adaptation shaders replace the constants `-10`, `64/30`, `30/64`, `0.4` and `0.9` with the parameter block's `d` and `e` vectors, computed on the CPU from the plan as `(64 / span) as f32` and so on; at the default these are bit-identical to the constants the WGSL compiler folded (checked by the unchanged histogram, adaptation and golden tests). The parameter block grows from 48 to 80 bytes; it is not part of the frame-target share (REND-020 counts targets).

**Loading.** `lookload::load(&Options)` resolves `--look`, else `<stem>.look.toml` beside `--world`, else defaults. `run` calls it for `editor` and `test-render` before any world or device exists, so a bad file fails fast with the path, key and value; `generate` refuses `--look` (a look never changes a tile). The viewer shows the debug path, so the result is reported (one line, only when a file is used) and kept as a `LookSet` for the lit viewer; wiring the lit plan into the window is later work (the plan builders `fixed_with` / `adaptive_with` take the body's `LookParams`).

**Class and bound (ADR 0035).** All attributes are presentation data; the table in LOOK-001 states each one's range and precision bound, and the bounds follow from the attribute's purpose (a valid sun, a valid EV, a histogram that has bins), not from measured results.

**Open point.** ADR 0042 point 6 lists "atmosphere coefficients, liquid appearance, albedo tables" in the look file; this change creates none of those tables (their items define them). The sibling-file discovery (`<stem>.look.toml`) is this change's reading of "beside the world definition"; an explicit `--look` overrides it.
