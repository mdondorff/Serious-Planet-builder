## Decisions

- **How a draw names its block.** A draw has one vertex buffer bound; `base_vertex` offsets into it. The main pool is several blocks (256 slots each) plus the small vertex pool, each its own `wgpu::Buffer`, and bindless vertex buffers do not exist in wgpu. So the draw list groups *consecutive* nodes that sit in one buffer into a run, binds that buffer once and issues one `multi_draw_indexed_indirect` per run; the records stay in the plan's order, so the draw order (and with it every depth tie) is the per-draw loop's. Cost: the number of multi-draws is the number of buffer changes along the plan, between 1 and the node count. The free-list placement hands out low slots first, so a settled view mostly sits in few blocks; a scattered residency can approach one run per node (then the path degrades to the per-draw count of commands, without the per-draw bind-group switch). A later change may stable-sort the nodes by block if the measured run count shows it pays (it would change tie order between tiles, so it needs the golden check). `TerrainStats::encoded_draws` reports the commands encoded.
- **Features.** `multi_draw_indexed_indirect` is core in wgpu 30 (the old `MULTI_DRAW_INDIRECT` feature is gone; backends without native multi-draw loop inside wgpu) and needs the downlevel `INDIRECT_EXECUTION` flag; a non-zero `first_instance` in an indirect draw needs the `INDIRECT_FIRST_INSTANCE` feature, which the context requests when the adapter has it. `GpuContext::indirect_draw_supported` is both. Without it the renderer keeps the per-draw loop (`set_draw_mode(Indirect)` returns the mode in effect). Tested on WARP (Dx12, Microsoft Basic Render Driver) and the RTX (see the PR); lavapipe is covered by Linux CI, where the tier C identity test passes whichever way the adapter answers (it asserts the fallback when unsupported).
- **Node records.** A read-only storage buffer in the vertex and fragment stages (the fragment shader needs the colour and grid phases). `first_instance` is the node index; WGSL's `instance_index` includes it. The per-draw path passes the same index through `draw_indexed(.., i..i+1)`, so both paths run one shader and one pipeline. REND-005 stays true: the records are camera-relative origins, colours, morph distances and grid fractions, as before.
- **Ring.** Globals, node records and argument records are written with `queue.write_buffer`, which the queue orders against earlier submissions, so a frame in flight would keep its data even with one set; the ring of two sets (`MAX_FRAMES_IN_FLIGHT`) makes the rule explicit (the pipelining rule of STRM-016: a frame in flight is never overwritten) and survives a later move to mapped staging. A plan larger than the ring's capacity re-creates the whole ring (frames in flight keep the old buffers alive).
- **Accounting.** The ring counts against the share's node-record bytes; the pure model is unchanged, `node_buffer_bytes` reports the live ring.
