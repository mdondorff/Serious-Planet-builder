## Design

**Nodes.** A vertex of the cube-face grid has a raw id `face (res+1)^2 + j (res+1) + i`; the copies of a vertex on a shared face edge (2, or 3 at the 8 cube corners) are one node whose id is the smallest raw id of its copies. The copies are found from exact integer cube points (`res n + (2i - res) U + (2j - res) V`, a face holds a point when its normal coordinate is `res`), never from floating point. A node has 4 neighbours (3 at a corner): the union of the in-face neighbours of its copies.

**Components and area.** A vertex is sea when `f64::from(continent) <= SEA_LEVEL_C`. Components are the 4-connected sea sets over nodes, labelled by their smallest node id. The area of a vertex copy is the solid angle of its dual cell clipped to its face, from the closed form of a rectangle of the tangent plane (`F(u,v) = atan(uv / sqrt(1+u^2+v^2))`, `libm::atan`), in fixed point at 2^-48 of the unit sphere (a 16384-cell face cell is about 2e6 units, the whole sphere 3.5e15, far inside `u64`). Every copy of a node adds its own dual cell, so the six faces sum to the sphere. Integer sums make the component areas independent of the order and number of threads; the threshold is `fraction * 4 pi 2^48` truncated.

**The tiled union-find.** One tile is one bake block. `analyse_block` (a pure function of the block, run on the worker that baked it): scanline union-find with minimal-index roots over the `(B+1)^2` sea mask; per local component the label (smallest node id, which needs a check only at face-edge vertices), the nodes and area over the vertices the block *owns* (a partition of every face: a block owns all its vertices except the far border it shares with the next block, and the last block of a row or column owns that too, so a shared vertex is counted once), and whether it touches the block border. The unions across the border are reported per maximal **run** of sea along a side of the block (the local label with the run's smallest node id) and per sea corner. Two blocks (or two faces) that share a run report the same set of vertices and so the same node; the corner records join blocks that meet only in a corner (diagonal neighbours, the three faces of a cube corner). The merge sorts all keys, runs a union-find with minimal roots over their indices and sums per root: the order the blocks arrive in cannot change a bit. Interior components (no vertex on the border) are final in their block. `ocean_bits` labels the block again and sets the bit of every vertex whose local label is in the list of ocean labels. The serial reference (`reference_ocean`) is an explicit-queue fill over the node graph with no code shared except the vertex area formula, which has its own tests (the sum is the sphere to the rounding of each vertex, the mid-face cell is the geometric `(pi/2/res)^2` to 1 %).

**Memory.** A block needs about 10 bytes per vertex beyond its samples while it is analysed (mask, union-find, labels; the area corners are two rows). The merger keeps one record per local component and per run: 1,056 bytes for the five components of a 1024-cell bake, tens of kilobytes at 16384. Blocks that were not baked in this run are decoded in batches of the bake's batch size (`batch_blocks`), so at most `min(threads, 1 GiB / block bytes)` blocks are decoded at once; a decoded block is 33.6 MB raw plus samples (the existing decoder) plus 10 MB analysis, about 44 MB per in-flight block at 1024 cells.

**Storage.** One bit per vertex per block, `(B+1)^2/8` bytes raw, LZ4 (runs of equal bits). A separate record kind (4) beside the sample blocks, because the answer is known only after every block has been seen: the bake writes sample blocks first (analysing each on its worker), the merge happens, then the second pass reads the blocks back from the store (the writer's index is written first) and appends the ocean blocks. The area threshold is part of the ocean block's key as an output parameter (not of the bake's stage key: it changes no sample), so a world with another threshold adds its channel beside the first without baking again. A second build with all ocean blocks present does not recompute the table.

**W.** `WaterField` holds a face mapping, the bake as a `LatticeSource` and a list of producers, most specific first. A query computes the lattice position once (`locate_direction`) and the interpolated bake once (`read_direction`, whose arithmetic is unchanged: it now calls `locate_direction`). The sea producer applies ADR 0041 point 1: land is the interpolated continentalness above sea level; otherwise the point is sea when at least one of the vertices with a non-zero weight (the lower corner always, the others when their axis weight is not zero) is ocean. The set is the same from either face of a shared edge, because the copies of an edge vertex are one node with one bit. The producer refuses an ocean channel of another resolution than the bake. The sea's `body` is a constant (`WaterBodyId::SEA`), its `kind` and `level` come from the definition. Per-tile storage of W is **not** decided here: the water pass (item 7) needs the water class per vertex of the water tiles, and the choice (a mask in the compact tile's reserved bits, a tile-local bit plane, or a CPU query per tile at plan time) depends on what the pass reads; the field is queryable by direction today, and nothing stored depends on it, so there is no `MESH_VERSION` change.

**Liquids.** Nine floats per row, keyed `liquid.<k>.<field>`; no node means the Earth table (water). The sea of a body is three optional nodes with Earth defaults, read without recording by the bake (the one number the channel depends on, the area threshold, is in the ocean block key) and with recording by a generator through `GenContext::sea`/`liquids`, so adding a node to a world changes the read set of exactly the generators that read it. The tension between ADR 0041 point 3 ("appearance is look data") and the owner's constraint 3 (the table in the definition with colour, emission, viscosity and waves) is resolved by keeping the physical parameters in the definition and leaving presentation overrides (absorption, roughness, foam) to the look file; recorded as a proposed ADR.

**Versions.** `GLOBAL_VERSION` 4 (the channel is part of the global stage; the four sample channels are unchanged, which the known-answer words show: only the grid hash that names the version moves). The climate version word folds it, so every mesh key moves; `MESH_VERSION`, `CLIMATE_VERSION` and `READER_VERSION` are unchanged. Definition schema version 2 (identity migration). Key format tag unchanged (a new kind byte and a new output-parameter tag do not alias).
