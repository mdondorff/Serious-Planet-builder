## Why
M5 item 6 (ADR 0041 points 1 to 3, accepted after SPIKE-08; the owner's M5 constraints 1 to 3 and 5). The terrain has an ocean floor, but nothing says which low areas hold water: the bake marks land by continentalness only, so an inland basin below sea level would be flooded by any pass that reads continentalness alone, and the water level is a constant in the shader's plan. The water pass of item 7 needs three things first: an **ocean-connectivity channel** in the global bake (a low area is sea only if it connects to the ocean), the **water-level field W** with a water-body id and a liquid kind next to `height(dir)` (the sea is the only producer in M5; lakes, rivers and lava plug in later as further producers), and **liquid kinds as world data** (a parameter table in the definition, not a code enum).

## What Changes
- `generators::ocean` (GPU-free, GEN-022): sea vertices (`continent <= SEA_LEVEL_C`), 4-connectivity on the six cube-face grids with the copies of a face-edge vertex as one node (exact integer cube points), components labelled by their smallest node id, area as the solid angle of the dual cells in fixed point (2^-48 of the unit sphere; integer sums, so thread count and order cannot matter), ocean = a component at or above the area threshold (a fraction of the body's surface, body data, Earth default 1e6 km^2). Computed by a **tiled union-find, one tile per bake block**: each block is analysed while it is in memory (local scanline union-find with minimal roots, areas and node counts over the vertices the block owns, unions across its border as one record per run of sea along a side and per corner), the reports are merged in a global union-find over node ids, and a second pass writes one bit per vertex. A serial queue-fill reference is the oracle; the result is bit-identical for every block size, thread count and block order.
- `cache::global_store` (STRM-023): the channel is stored as blocks of a new kind (`Kind::GlobalOcean` = 4, one bit per vertex, LZ4), keyed by the tile, `B`, `res`, the bake's stage key and the area threshold; `build_global` analyses baked blocks on their worker threads, decodes and analyses the blocks it did not bake, writes the ocean blocks the store lacks and recomputes nothing when all are there; `StoreOceanSource` reads it; `verify_global` checks ocean blocks against the channel recomputed from the stored blocks; `generate --global-dir` prints the channel's blocks, components and cost.
- `generators::water` (GEN-023): the field W: `WaterField` over `WaterProducer`s, the sea producer (interpolated continentalness at or below sea level and at least one weighted lattice vertex ocean-connected, ADR 0041 point 1), `WaterSample { level_m, body, kind }`, `plan_water` (GPU-free plan data). `LatticePos`/`locate_direction` expose the lattice position `read_direction` uses.
- `world-def` (WDEF-006): the liquid table (`liquid.<k>.colour_*`, `emission_*`, `viscosity_pa_s`, `wave_amplitude_m`, `wave_length_m`; Earth default one liquid, water, when the world defines none) and the sea of a body (`body.<n>.sea.level_m`, `.liquid`, `.min_area_fraction`, Earth defaults). Schema version 1 to 2 with an identity migration (version 2 only adds keys), a v2 fixture, typed paths, validation.
- `LitPlan::with_water_level`: the viewer sets the plan's W from the sea of the definition; the default level 0 leaves plan text and hash unchanged.
- `GLOBAL_VERSION` 3 to 4. Every key under the bake's version is new: stored bakes (blocks and stage key), the packs pre-filled from them and, through the climate version word, every stored mesh are unreachable (no `MESH_VERSION` bump: the layout did not change). Item 8 regenerates the 16384 store.
- The retrofit test (ADR 0041 point 7): one synthetic lake (a basin with a fixed level, its own body id and a lava kind) goes through the same `WaterField` path as the sea; the sea's answers do not change, the plan data follows the lake.

## Impact
Specs: GEN-022, GEN-023, STRM-023 and WDEF-006 added; WDEF-002 and LOOK-007 modified. Each new attribute states its class and bound (ADR 0035). Pins re-recorded with the version: the global known answers and grid hash, the reader pins, the climate and compact hashes and version word, the Reference mesh key, the persistent mesh, stage and block keys, the determinism manifest (plus the ocean table and channel hashes), the terrain plan snapshots (mesh keys only), the app manifest pins. The definition hash of a world without a liquid table or sea is unchanged.

Expected golden changes: none. No sample value, mesh geometry or shader changes; the debug-path and shaded goldens do not read the new data. The pending lit and sky candidates are unaffected (the plan's W is 0 as before).
