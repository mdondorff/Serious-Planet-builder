## Design

**Where things live (CON-02, CON-03).** Decisions are GPU-free and display-free: `frame::adapter` (the gate), `frame::freecam` (the pose function), `frame::viewer` (flight clock, commands, free-camera mode, frame statistics, readiness report, title). `render` holds `gate` (enumeration and description of wgpu adapters) and `window` (surface, blit). `app::window` is the `winit` loop: it turns key events into `Command`s and held keys and calls the above; `key_command` and `set_held` are the whole mapping and are tested without a window.

**Adapter gate.** `select(adapters, requirements, mode)` orders the candidates deterministically (Vulkan, then Dx12, then others; then name; then position; this picks Vulkan on the RTX like the existing goldens) and returns the first acceptable one or a `Refusal` listing a reason for every adapter. `Interactive` accepts discrete GPUs only; `TestSoftware` accepts software adapters only (so that test runs stay reproducible). Requirements are the wgpu default limits the device is requested with (named: `max_texture_dimension_2d`, `max_buffer_size`, ...) and no required feature today (`TIMESTAMP_QUERY` and `INDIRECT_FIRST_INSTANCE` have fallbacks and are requested when present). The window adds `can_present`. `GpuContext::new(HighPerformance)` (perf, `test gpu --real`) uses the same gate; `Software` keeps the platform fallback adapter. The interactive editor refuses `--adapter software`; `--smoke` is the test mode and honours `PLANET_ADAPTER` (software by default).

**Flight clock.** `FlightClock` is banked milliseconds plus a run start on an injected millisecond clock; pause, resume, toggle and restart are pure. `camera_at(cameras, t)` interpolates between the 60 Hz cameras of the script so a faster window moves smoothly, and loops after the end (a cut). The free camera pauses the clock; returning resumes unless the user paused.

**Free camera.** `FreePose { position, heading, pitch }`. A frame: look first (yaw about the local vertical, pitch clamped to 89 degrees), then move along the new view. The horizontal part is an arc of a great circle: position and heading are rotated about the same axis, which is parallel transport and has no pole; the vertical part changes the distance from the centre. The arc angle over a frame is the integral of speed/r with r changing at a constant rate, `(h/r0) * ln(1+x)/x` with `x = v/r0`, so two half frames equal one whole frame and the opposite keys undo a move exactly. Speed is height above terrain times `heights_per_second` within limits (the controller's `ControllerParams`); the caller supplies the height and, after the move, the ground radius for the clearance lift. Input = `CameraInput` (key axes and rates) plus `look_delta_rad` (yaw right, pitch up). The existing `CameraController` (REND-010) is untouched.

**Presentation.** The terrain renderer keeps its internal resolution (`--size`, default 1280x720); `WindowSurface::present` blits its colour target into the swap chain with a fit viewport and black bars, so resizing never rebuilds the renderer. The surface format is the first non-sRGB format (the debug path's colours are display-encoded). Outdated, lost, timeout and occluded surface states are skips, not errors; `Validation` is an error.

**Readiness report.** `Readiness { bake, prefill, view }` is GPU-free data. Today the bake is complete when the world opens (`WorldTerrain::bake_blocks`, equal done and total); the pre-fill counts come from the stored pack (`prefill_present`) or are absent for an in-memory bake; view coverage is the share of the newest plan's wanted tiles drawn at their own level plus the mean lag in levels (the unweighted detail lag, TEST-018). The incremental first-visit bake of ADR 0045 point 5 will report its progress through the same struct.

**GPU time.** The pipelined loop never waits; one frame a second is rendered `timed` (it waits for the GPU and reads the timestamps), and the title shows that sample, `gpu n/a` without timestamps. Its CPU time excludes the wait.

**No display.** The event loop is created before the world is built; a failure returns an error starting with `no display: `. The smoke test spawns the real binary (the event loop wants the main thread), and treats that error as a skip only when `PLANET_NO_DISPLAY` declares it (the CI Linux job does).

**Deviation noted.** ADR 0042 point 4 says the title shows the GPU time "meaningful with vsync off": the one-a-second timed frame gives a value at any vsync; with vsync on the number is still the pass time, not the frame time.
