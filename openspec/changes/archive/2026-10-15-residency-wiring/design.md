## Decisions

- **R comes from the worker, after the plan, on the plan's cache (no second cold evaluation).** The job publishes the plan first, then selects R with `residency_set_field` on the same `SelectionCache` and the same field, and publishes it as a second result (`take_residency`); a frame never waits for either. What the cache holds is per tile and a pure function of the tile: the geometry and the height-aware volume. The plan's frustum cut visited a subset of the tiles the position-only selection visits, so R finds those as hits and computes the volumes of the others once. R needs no origin height and no mesh key at all: the origin and key of a resident tile are those of its mesh, so the origin heights the plan evaluated on worker threads (the expensive part at altitude: bake blocks) are not touched again. A test on a counting field pins this: R after the plan adds zero `height` calls, a repeat of R or R for a turned view adds zero `height` and zero `height_bounds` calls, and the plan of the turned view finds every volume in the cache. R's own new volumes are evaluated serially inside the job; at altitude they may read bake blocks the plan did not (not measured). R runs after the plan is delivered, so it delays the next plan, not a frame.
- **R is reused when the position and parameters repeat.** The worker keeps the last R with its key (position, LOD parameters, face mapping, seed). A request that differs only in the view direction (every rotation) gets the same `Arc<ResidencySet>` in the same job: nothing is selected. The loop rebuilds the manager's residency wants only when the set changes (pointer comparison) and the draw wants only when a new plan arrives.
- **Wants lag by one iteration, as before.** The manager's frame uses the wants of the plan and R delivered up to the previous iteration (the pipeline delivers in `begin_frame`, which runs after the manager). Until the first R arrives the residency wants are empty and only D is asked for; after a jump the old R stays in the wants until the new one arrives (R follows its plan in the same job), so the old surroundings are kept a little longer and never cancelled early.
- **The manager is the only owner of placement.** The streamer reserves a slot at dispatch; when a tile completes, the loop writes it into that slot with `upload_at` and records it in the mirror the pipeline draws from. Evicted tiles are forgotten (no pool is touched; the manager's free list owns the slot). `Streamer::take_changes` hands the loop the additions and evictions in order, so the loop does not scan the resident set (up to 14,000 tiles) every iteration; a tile added and evicted before the loop looked is skipped because the loop acts on the state at drain time. The mirror is checked in every tier-A frame: the sink holds exactly the streamer's resident tiles, in the assigned slots, no slot twice.
- **Retirement counts iterations.** The streamer's frame counter advances once per iteration (including iterations that draw nothing) and the loop sets `retire_frames` = `MAX_FRAMES_IN_FLIGHT`, so a given-back slot is rewritten at least that many iterations later, which is at least that many frames after the last frame that read it was submitted. wgpu orders `write_buffer` after earlier submissions on the queue, so the rule is belt and braces on top of the queue order; it is the same rule the renderer's own pools use.
- **Capacity is the renderer's pool.** `StreamConfig::capacity` is `pool_config().main_slots()` and `vertex_pool_slots` the pool's vertex slots, so the manager never assigns a slot the renderer does not have. At the mid share this is far above R at the standard views (R at most 38 % of the vertex-format slots), so in the standard scenes nothing degrades; the small-share behaviour is exercised at tier A through the loop.
- **Settling stays defined by the draw set.** The harness ends a view when the frame is the synchronous frame (the plan made for exactly the request, every node resident). Filling the rest of R continues while the next view is set up, and whatever is still on its way when the script ends is dropped with the streamer; the image does not depend on R.
- **`--stream` keeps its contract.** It plans with a cache, selects R on that cache (a synchronous run: there is no frame to protect), asks the manager for D then R within the mid share, and returns when D is resident, with the same meshes as before. The existing stream-equality test passes unchanged.
- **Counts per iteration, in the existing log.** `FrameCounts` follow the time columns of the pipelined log (names fixed in `FrameCounts::NAMES`); the run summary prints the cumulative slot figures. `degraded` is the number of tiles of R replaced by ancestors in that iteration's fit (ADR 0031 point 4b), which is nonzero every iteration while R does not fit the share.

## Risks

- The manager fits R every iteration (`degrade` builds sets of R plus ancestors) and the streamer builds its needed map from R each iteration: O(|R|) per frame on the frame thread. At the largest standard R (14,325 tiles) this is not measured; the scheduler column of the log reports it and the architect's perf window decides whether to cache the fit per change of the wants. Not optimised here.
- R is selected serially after the plan; at altitude its volumes may read bake blocks the plan did not. It delays the next plan, not a frame; measured only in a perf window.
