## Why

M4 item 7, the wiring change that #132 (frame pipelining) left open. The scheduler (#127) and the residency manager (#128) exist and are tested on fakes, but the interactive loop still asks the bare `Streamer::begin_frame` for the draw set and uploads every tile through `upload` into slots the renderer chooses; the `--stream` path does the same. The scheduler's classes, the residency set R, the share counted in slots, eviction and degradation (ADR 0031 points 2-4, ADR 0033 points 1-3) therefore have no effect on a running frame. #132 named what wiring needs: R from the plan worker (a second cold evaluation unless it shares the plan's work), slots placed through `upload_at`, and `--stream` equal to the synchronous frame.

## What Changes

- frame, `pipeline`: `PlanField::residency` (R of a request's camera position, position only) and `residency_of`. The worker computes R in the same job as the plan, after the plan is published (no frame waits for R), on the plan's own `SelectionCache`: the tile geometry and height volumes the plan computed are hits, R needs no origin height and no mesh key (a resident tile carries its own), and adds only the volumes of the tiles outside the frustum. A request with the same position and parameters as the previous R reuses it (`ResidencyOutcome::reused`), so a rotation selects nothing. `PlanPipeline` delivers it (`residency()`), `WorkerCounts` counts selected and reused sets.
- frame, `managed` (GPU-free): `ManagedLoop` = pipeline + `ResidencyManager`, one call per iteration: the manager fits and requests (draw-set misses first, then the rest of R, prefetch empty), the changes of the resident set are executed on a `TileSink` (`upload_at` into the manager's slot, `forget` on eviction), the pipeline draws from what the sink holds. `FrameCounts` (resident, in flight, queued, dispatched, cancelled, blocked, evicted, uploaded, degraded) per iteration.
- streaming: `StreamConfig::record_changes` and `Streamer::take_changes` (the resident-set changes in order, off by default), `StreamStats::dispatched`.
- app: the pipelined loop runs on `ManagedLoop` with the renderer as the sink (`upload_at`/`forget`); its capacity is the renderer's pool (`pool_config`), `retire_frames` = frames in flight. `--stream` uses the manager with R selected on the plan's cache; it draws the same meshes. The per-frame log gains the count columns after the time columns; the run summary reports the slot counts.
- spec: STRM-005, STRM-006, STRM-007, STRM-015, STRM-016 gain the scenarios and sentences listed in the spec delta; STRM-017 (managed frame loop) added.
- tests: tier A through the loop on fake clock, I/O and spawners (rotation requests, dispatches, cancels, uploads and evicts nothing once R is resident; teleport fill order; small share per frame; sink mirrors the streamer; R shares the plan's cache; thread-count independence and reuse), a streamer test for the change log; tier C on the software adapter (pipelined and `--stream` images equal the synchronous ones, count columns present).

Not in this change: the prefetch source (the class exists and is empty), the per-frame upload cap and the RAM budget (ADR 0033 points 8 and 9, proposed), the compact tile, indirect multi-draw, the perf scenes (the architect measures), GPU time of submitted frames, ordering R by the view direction (allowed by ADR 0031, not done).

No golden, pinned count, plan snapshot or MESH_VERSION changes.
