## Decisions

- **The format is a context preference, like the draw mode.** `GpuContext::prefer_tile_format` (set by `--tile-format`) is read by `TerrainRenderer::for_context` and by the app's tile builders, so the flight, perf, pipelined and stream paths need no extra parameter. Default compact. The vertex format is the reference and runs the same plans.
- **Goldens.** The goldens are drawn from the product's tile path now. A golden that moves must stay within rounding or a declared model change; WARP candidates produced on a machine whose WARP driver version differs from the recorded one (`driver.txt`) escalate by rule whatever their numbers, so the real classification uses the CI candidates (Windows WARP and Linux lavapipe) and the owner's real-GPU run.
- **Renamed `TileData` to `RenderTile`** in `generators::compact`: `generators::TileData` is the height tile (a different type) and the two collided in the app.
- **Plans, pinned counts and upload bytes.** The plan's `upload_bytes` (TEST-011) stays the vertex-format reference count; the renderer's own upload is the compact figure (asserted per tile format in `gpu_terrain`: 217,924 B against 1,146,684 B at high-2000km). No pinned plan count changes.
- **Cells below 32.** The tests and `--stream`/`--pipelined` views use 16 cells; the compact pools take fewer atlases there (14 at the mid share) instead of refusing.
- **Indicative timings** (RTX 3080 Ti Laptop, ground-1m, 2,936 nodes, 2560x1440, same process, interleaved, NOT a perf-window measurement): compact GPU median 1.17 against 1.11 ms (level view, 1.05x), 2.78 against 2.34 ms (relief, 1.19x); CPU encode 1.10 against 1.06 ms (indirect) and 1.18 against 1.34 ms (per-draw); upload 26.0 MB against 157.7 MB. The spike measured 0.8-0.93x with 8-bit normals and a uniform per node; with 16-bit normals, the record in a storage buffer and 8-byte texels the vertex stage is not faster here. GPU clock state not controlled (ADR 0034 proposed).
