## Step 1: edit-invalidation-reach

Source: ADR 0066 points 1, 2 and 5 (the bounds half is step 3), SPIKE-13 variant D, M3 gate condition 2.

### Today
- A tile's items come from `GenContext::query_tile`: cells of the tile's footprint plus a margin ring, each recorded as `ReadRecord::Cell`, or the whole body (`ReadRecord::Body`) over `max_cells`. The key entry is kind 1 (cell) or kind 2 (body); the result is the cell's items as `(id u64, content u64, direction bits)`.
- An item is `(id u64, content hash u64, unit direction)`. It has no reach, layer or priority. No production field reads items yet; the readers are the test fields of `crates/cache/tests/keys.rs` and `crates/generators/tests/cell_keys.rs`.
- Consequence (SPIKE-13): an edit re-keys every tile that reads the cell or its ring, 59 to 83 % of the resident tiles for a 150 m stamp.

### Decisions
1. **Item record.** `put_item` keeps its arguments; a new `put_item_spec(body, ItemSpec)` carries `id`, `layer` (non-empty UTF-8 name), `priority` (i32), `dir`, `content`, `reach_m`, `max_delta_m`. `put_item` is `put_item_spec` with layer `"items"`, priority 0, `reach_m` 0 and `max_delta_m` 0, so the existing tests keep meaning what they say. `reach_m` and `max_delta_m` are finite and at least 0; `reach_m` above `CELL_EDGE_M` (the nominal 40 km, not the real cell edge of the body) is refused with the id and the limit (ADR 0066 point 1) and leaves the definition unchanged. Because the limit does not depend on the radius, a radius edit cannot leave an item over it.
2. **Ids and hashes stay `u64` in the API.** ADR 0066 writes 16-byte ids and 128-bit item hashes; their parsed form arrives with the item files (E2/E4). In the result material an id is its `u64` zero-extended to 16 bytes (big-endian, so the order is the numeric order) and a content hash is derived in 128 bits from `(content u64, direction bits, reach bits, max_delta bits, layer, priority)` under `planet-builder footprint item v1` (WDEF-003 rules: `-0.0` read as `0.0`, also in the direction). `planet-builder item hash v1` stays for the item file's content hash over its parsed form (E2), so the two layouts never share a domain. The key encoding writes the full 16-byte id and 16-byte content hash now, so the switch to ULIDs changes a type, not the encoding (opus-planner's condition a). The switch to 128-bit ids is a task of whichever of E2 and E4 first reads or writes item files, before any item file exists (condition b; ADR 0021 point 4, ADR 0023 point 2).
3. **Query kind 3, `ReadRecord::Footprint { body, layer, tile, halo, items }`.** `GenContext::query_footprint(body, layer, tile, halo)` returns the items of the layer whose reach touches the tile and records the entry.
   - Parameters (canonical bytes): `body u32 | layer (u32 length + UTF-8) | tile raw id u64 | halo f64 bits` (halo a fraction of the tile edge, `-0.0` read as `0.0`, a halo outside `[0, 1]` or not finite is refused).
   - Result: items in application order `(priority i32, id big-endian)`, each `id 16 B | content hash 16 B`, under the context `planet-builder footprint result v1`; an empty result is that context over empty input.
   - Candidates come from the cell index: the cell of a tile at or below the cell level plus as many rings as hold the cap's arc and the longest reach over the narrowest cell edge (half the nominal width: the level rounding and the face warp; at most 16 rings, else the scan). A tile coarser than the cell level scans the items of the body instead (correct and O(items); step 1b replaces the scan by region summaries). The ring count is checked, not assumed: a test compares the index result with a scan of every item and another places items at known distances from sample points of the tile and its halo.
   - Test: the great-circle distance between the item's anchor and the tile's centre direction is at most `tile_cap + halo_extra + reach_m / R`, all in f64 with `libm`, with a fixed relative margin of `2^-20` plus `1e-12` rad (a false positive changes a key and never an output; a false negative is a defect). The tile cap is the largest angle from the tile centre to its corners and edge midpoints, taken on the tangent-warp mapping, enlarged by the halo.
   - A halo that takes the extended face coordinate beyond 1.5 (the coarsest tiles) makes the cap the whole sphere: the warp is not usable far past a face.
   - Cells and ids that are not reached never enter the result, so moving an item out of every tile's reach changes no key (the SPIKE-13 finding).
4. **64-bit path.** `ReadRecord::hash64` for a footprint record is the 64-bit hash of the same result (items, application order), so `inputs_hash_for` and the persistent key follow the same reads (the invariant of `read_records_for`).
5. **Format tag.** `KEY_FORMAT_TAG` stays 2 for every key that carries no kind 3 or 4 entry; a key that carries one starts with tag 3. A new entry kind that old keys never contain aliases no old key, and bumping the tag for all keys would invalidate the global bake, the pre-filled coarse tiles and every pack on disk (hours of regeneration) for no gain. This is the reading of ADR 0066 point 2 (a per-key tag, not a global bump; opus-planner, 2026-10-19). Tier-A test: a key without footprint entries is byte-identical to today's key (known answers unchanged), a key with one starts with tag 3, and the two never share an encoding.
6. **Contract test (M3 gate condition 2, ADR 0021 point 7).** A test field that declares footprint reads and a generator that actually samples items are run over a world; a recording context observes every item the generator touches; the test fails when a touched item is absent from the declared result (declared versus recorded), and asserts the stage output is unchanged beyond `reach_m` and within `max_delta_m` (ADR 0066 Consequences).
7. **Node set id per tile (STRM-010, ADR 0025 point 3).** For a field that `reads_cells` the id covers the field-wide read paths, the radius node and the paths of the tile's own queries (kind, body, layer, tile id, halo; never the result), so it stays a function of which reads are made and not of their values, and equal for equal tiles. Fields without cell reads keep the per-world id (known answer unchanged).
8. **Tile-level GEN-017 test.** M3 gate condition 2 names it without a definition (ADR 0025 and the M3 report are silent); meaning, confirmed by opus-planner: a tile generated alone equals the same tile cut from the field or bake, for a stage that reads items. Step 1 tests it with a stamp stage over `Reference` (a child tile's grid equals the parent's grid cut at the child's samples, bit for bit, whatever the generation order); the same assertion over the eroded base arrives with E2, the first real stage.

### Notes from the spec review
- The definition hash of a definition with items now covers reach, bound, priority and layer; `HASH_VERSION` is not bumped because nothing persisted holds such a hash yet (WDEF-005 "Hashes" is unchanged in meaning).
- WDEF-004's sentence "spatial queries record the hash of each cell read" is edited with E2 (ADR 0066 Consequences), when the first item-reading stage lands; footprint reads are recorded by the same mechanism.
- `node_set_id_of_tile` exists and is tested; the record writers (`meshpack.rs`, `tiles.rs`) keep the per-world id until a stored stage reads items (E2). The STRM-010 delta says so.
- A tile coarser than the cell level scans the items of the body; a tile at or below it uses the cell index with 5 rings. The cap of a coarse tile overshoots the tile and a fixed ring count would omit items the scan returns (false positives only, but a key must not depend on the path), so the two paths are made to agree by construction.

### Not in this step
Region summaries (kind 4, step 1b), the streamer and the plan (step 2), the `SelectionCache` and the bounds (step 3), item files and the stamp stage (E2, E4). No production field changes, so no golden moves.

### Numerics
The footprint test and the tile cap are f64 with `libm::atan2`, `libm::sqrt`; no `f32`, no `std` transcendentals (CON-14). The numerics-reviewer reads the key encoding (kind 3 parameters, the result material, the item hash) and the margin before the PR.

## Step 1b: edit-invalidation-summaries

Source: ADR 0066 point 3. A tile coarser than the cell level scans the body (step 1) and its kind 3 entry carries the hash of every item that touches it: a tile of level 3 over a world with thousands of items has a long result and every edit under it re-keys it, which is right, but the recorded read grows with the item count. Region summaries replace that read for the tiles that cover many cells.

### Decisions
1. **Which tiles.** A tile that covers more than `SUMMARY_MIN_CELLS` = 64 cells (`tile.level() + 3 <= cell level`) records kind 4 entries; every other tile records kind 3 as in step 1. The items the generator receives are the same (the footprint result); only what the key records differs.
2. **The tree.** Per `(body, layer)` a Merkle quadtree over the cell grid. A leaf is a cell at the cell level; its hash is BLAKE3-128 under `planet-builder cell hash v1` over the cell's item rows in application order, each row `id 16 B | footprint item hash 16 B` (the rows of kind 3, so the item hash is written once; `footprint_item_hash128` and `footprint_id_bytes` move from `cache` to `world-def`, `cache::key` re-exports them). An inner node at level `l` is BLAKE3-128 under `planet-builder summary node v1` over `l u8` and its four child hashes in the order (0,0), (1,0), (0,1), (1,1) of `TileId::children`. An empty subtree is the same function over empty children, so its hash depends on its level (`empty(l)`, computed from the cell level up). The roots are the six faces (level 0).
3. **Incremental.** `WorldDefinition` keeps the non-empty nodes in a map `(body, layer, level, node raw id) -> hash`; `put_item_spec` and `remove_item` rewrite the item's cell and one node per level above it (at most `cell level` nodes, 8 at Earth's radius); a radius edit that changes the cell level rebuilds the body's trees. The tree is derived data: it is not in the definition hash and not compared in `PartialEq` beyond what the items already fix (it is rebuilt equal from equal items).
4. **The read.** For a coarse tile the cells that matter are the tile's own cells plus a ring of margin cells around it: thickness `ceil((cap arc - 0.9 x distance from the tile centre to the nearest edge midpoint + 40 km) / narrowest cell edge) + 1` cells, where the cap is the footprint cap of the tile with its halo (step 1) and the narrowest cell edge is half the nominal width (step 1). The node set is the smallest set of quadtree nodes that covers exactly the tile's cells (the tile itself is one node) and the margin ring's cells: cells are merged bottom-up while all four siblings are present. One `ReadRecord::SummaryNode { body, layer, node, hash }` per node; its key entry is kind 4, parameters `body u32 | layer (u32 length + UTF-8) | level u8 | node raw id u64`, result the node hash. A tile that needs more than 16 rings, or whose ring crosses the whole face, reads the six face roots (still correct, the largest false-positive set).
5. **Completeness.** An item that can touch the tile has its anchor inside the covered cells (the margin is derived from the same cap and reach limit as step 1's rings). An item whose anchor is in a covered cell but whose reach does not touch the tile re-keys the tile: a false positive, as in step 1.
6. **Tag.** A key with a kind 4 entry takes tag 3 (`QUERY_SUMMARY` already selects it in `encode`).
7. **Tests (tier A).** Edit inside the covered cells changes the coarse tile's keys; outside the margin changes none; an edit rewrites exactly one node per level (counted); `empty(l)` differs per level and is pinned; node hashes equal a from-scratch rebuild after any sequence of puts, moves and removes (property test); the nodes of a read cover exactly the cells they claim, with no overlaps; a coarse tile's footprint items are within the covered cells.
8. **Not in this step.** Storing the tree on disk (the tree is rebuilt from the items on load, cost O(items)), summary reads for the base field, any change to kind 3.
