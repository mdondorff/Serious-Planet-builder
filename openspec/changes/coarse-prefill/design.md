## Context

ADR 0045 point 3 (owner, 2026-10-16): the bake step also writes tile levels 0 to N (default 4) into the tile pack, with the existing keys, format and codec. The streamer today generates every tile (`MeshSource::load`), and the pack holds height tiles (kind 1, from `generate --cache-dir`, a verification product that nothing streams) and bake blocks (kind 3). A streamed tile is a `RenderTile`, a vertex mesh (levels 0-2 and finest-level fallbacks) or a compact tile (levels 3 and finer), built from the height field with normal stencils beyond the tile's own samples, so a height tile alone cannot rebuild it bit for bit.

## Decisions

- **What is stored**: the `RenderTile` itself, kind 2 (`Kind::Mesh`, a kind the key module already names and no record uses), payload = the exact bits (key, origin, vertices or control points and texels) behind a version, form and cells header and one LZ4 block. Reading it back gives a value equal to the generated one, so "bit-identical to on-demand" is `assert_eq!` on the tile and needs no tolerance.
- **Key**: the ADR 0018 mesh key of the tile (field, tile, cells, skirt fraction, `MESH_VERSION` via `mesh_key_inputs`) with one more output parameter, the form (vertex 0, compact 1). A different field, cells, mesh version or form is another key and therefore a miss. Levels 0-2 are always vertex, so their key ignores the form asked for. Nothing existing changes (no new key version, no `MESH_VERSION` bump).
- **Which tiles**: levels 0 to N, N at most 8, strictly below the run's finest level (a finest tile's form depends on its relief, CON-13, and its key carries the finest class). The reader looks up levels at most 8 below the finest level: a binary search in the in-RAM index plus a key hash.
- **Determinism (CON-14)**: tiles are generated on any number of threads with each result kept at its index, appended in the fixed order level, face, row, column. The pack bytes do not depend on the thread count; a test compares the files of a 1-thread and a 5-thread run.
- **Idempotence**: the missing set is computed with the same lookup the reader uses (current key, payload decodes); when it is empty no writer is opened (no lock, no index rewrite, no file time change). A record that does not decode counts as missing and a newer record wins.
- **Where it runs**: after `build_global` in `generate --global-dir`, and as `generate --prefill-dir DIR --global-res N` for an existing bake (the field is the one `WorldTerrain::open_store` builds, the one the perf scenes read). The tile form is the compact form (the discrete GPU's default); `--tile-format vertex` pre-fills for the reference form.
- **Perf scenes**: `dive-cold` opens its reader `cold()` (the same bake, the same field, a tile source that never consults the pack) rather than an empty pack beside the bake: nothing is copied or deleted, the store is shared, and the only difference between `dive` and `dive-cold` is one flag, so the log can state it. Each scene records the pack's state as a marker after the place in `protocol.source`; `compare` keys on the whole string, so a cold and a pre-filled log never compare.
- **Gate**: the marker is evidence the harness wrote after reading the pack (every tile of levels 0..=N decodes), not a flag the caller passes; `accept M4` reads it back. A log without a marker is treated as cold because it was measured from an empty tile cache.
- **Defaults and cost**: the default pre-fill is 4 levels, 2,046 tiles, about 22 MB (measured at 256 cells: 22.5 MB payload, 4.4 s on 20 threads). Existing tests that bake through `generate --global-dir` and do not test the pre-fill pass `--prefill-levels 0` so they stay fast.

## Risks

- A pre-fill depends on the field's persistent mesh key being cheap and exact for the eroded field over a stored bake; the first run at 16384 cells is the measurement (recorded in docs/log.md).
- The pack grows by the pre-fill (about 22 MB over 11.7 GB); compaction keeps kind-2 records (liveness is judged only for kinds it knows), so `cache-compact` neither drops nor refreshes them. A `MESH_VERSION` or field change leaves stale tiles that lookup treats as misses; a re-run of the pre-fill adds the current ones.
