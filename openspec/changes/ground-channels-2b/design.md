## What exists (checked 2026-11-05)
- **The driver block is the carrier already.** Every compact tile holds a driver block of 81 words, a 9 x 9 grid of texels across the tile, 4 bytes each: soil depth code, moisture code, insolation code, the neutral insolation code of the texel's latitude (GEN-074, `pack_driver_word`; the slot grew by 324 B, 9,168 to 9,488 B, ADR 0076). The terrain shader samples it bilinearly (`tile_drivers`) into the material inputs `SoilDepth`, `Moisture` and `Insolation` (LOOK-008; slots 5 to 7 of the 8 inputs). The tile builder fills it with the neutral values (`driver_block(map, id)`, soil 1 m, moisture 0.5): "the builder makes no other".
- **A per-tile field hook exists.** `HeightField::heights_and_climate(map, id, dirs, stop)` gives the builder the tile's climate from the field, so a field over a store gathers a tile's cells once (GEN-020). The drivers have no such hook yet.
- **The channels.** Kind 14: one record per face, `u8` codes `round(8 log2(area / cell area))` over the face's pass-1 cells. Kind 15: one record per pass-2 tile, `u8` codes `round(m)` of the deposited depth, 0 to 255 m in steps of 1 m; the removed depth is `max(0, deposited - change)` from kind 13. `LayerChannels::{area_log2_cells, area_cells, depth_m}(d)` read bilinearly at a direction through bounded LRUs of decoded faces and tiles; it borrows the store and the world (`LayerChannels<'a>`).
- **The layer read pattern.** `ErosionLayer` (generators, GPU-free) reads tiles through a `LayerSource` trait that the cache crate implements over the store (CON-02); `StoreLayer` is the store-backed source the viewer opens (VIEW-065).

## Decisions
1. **Carrier: the existing driver block, filled from the channels; no new block, no GPU interface change.** `SoilDepth` takes the deposited depth in metres (the byte over `soil_max_m` 8 m, 0.031 m a step), `Moisture` takes a wetness from the drainage area (a fixed ramp of the log2-cell code, documented as a table in the spec, 0 to 1), `Insolation` stays neutral until a stage supplies it. SPIKE-100 D1's two inputs ("read per tile like the driver block ... replace the neutral driver slots") land in slots that LOOK-008 reserved; the look's curves address them by name (`soil_depth`, `moisture`), so the look schema does not change. The debug views (GEN-071) show the new contents.
   - Alternative rejected for the first step: a second 81-word block or a texture array (+324 B a slot, 3.4 % fewer pool slots, a mesh version bump and a shader binding) for no input the current slots cannot carry.
2. **Reader placement: in the field, in the generation workers, at tile build.** A new default method `HeightField::drivers(map, id) -> Option<DriverBlock>` (None: neutral) beside `climate`, called by `compact_tile_field` for the tile's 81 texel directions; the field that reads the layer (the viewer's class and legacy fields, `with_erosion_if`) implements it over a `ChannelSource` trait (generators), implemented in the cache crate over `LayerChannels` (CON-02, as `LayerSource`). The streamer needs no change: it builds tiles through the field. Test fields keep the default, so every golden and the reference renderer stay neutral.
3. **Store handle lifetime.** `LayerChannels<'a>` borrows; the field must own. Add an owned variant (`Arc<TileStore>`, `Arc<GlobalWorld>` held by the world that already holds them for `StoreLayer`), so its lifetime is the field's and the viewer's. It is the same object I7 will read per point (decision 7): one decode cache for both.
4. **Memory and eviction.** Per tile: 0 bytes more in the slot (the block exists). Reader: the face LRU holds decoded kind-14 faces, `cells^2` bytes each (4,096 cells: 16.8 MB; 12,288: 151 MB; to be measured in PR 1 on the real store, with the decode time of a face); the tile LRU holds kind-15 tiles. Both stay bounded and shared by the six generation workers behind the existing mutexes; the sizes become options with defaults chosen from the measurement. A tile read touches at most 81 points, almost all in one face and one or two pass-2 tiles, so the caches hit after the first texel.
5. **Keys and versions.** The driver block content changes with the layer, so the field's key folds in the channel identity: the layer id, `CHANNELS_VERSION`, the code scales and a new `DRIVER_MAP_VERSION` for the code-to-input mapping of decision 1; `MESH_VERSION` is bumped when the builder first writes non-neutral words (GEN-025). A tile of a mesh pack carries the channels or is rebuilt. Changing the ramp re-keys only the viewer's tiles.
6. **Cost.** The shader already samples the driver block and mixes three components; the new inputs add no shader work. The per-tile build adds 81 bilinear reads from cached decoded data (CPU, in a worker).
7. **Relation to M9 I7 (channels as per-point primitives, R5).** I7 reads the same channels as CPU field values (rises 0, a gate) at a point, through the same owned reader; the per-tile block is the presentation path of the same data (ADR 0035), the CPU read is canonical (CON-07). Neither depends on the other; the reader of decision 3 is the shared piece, and the first PR below delivers it.

## Open branches and questions
- **D1, keep-pits (SPIKE-102).** If the owner keeps depressions, pass 1 adds a fill-depth channel (P1b, lake water at the fill level) next to kinds 14 and 15, a kind 16 owned by the explorer lane. It needs a third input slot: the eight inputs are all taken (5 to 7 by the drivers), so it adds `INPUTS` 8 to 9 (look schema bump, curve table 6 x 9 x 2 words) or a second driver block with the erosion depth for D1's "rock where erosion depth exceeds 2 m". If D1 is not decided when PR 2 starts, PR 2 implements decision 1 and leaves the input list as it is; the branch is then its own change.
- **Depth resolution (for the explorer lane).** Kind 15 codes the deposited depth in 1 m steps (`DEPTH_SCALE` 1, a key parameter), but SPIKE-100 D1's thresholds are 0.3, 0.5 and 1 m: bilinear blending of 1 m codes gives gradual transitions between texels, not a 0.3 m threshold. A finer scale (a quarter metre to 63 m, say) would serve D1; the writer owns the format, so this is a request via the planner, not a change here. Until then the thresholds in the look are tuned on what the codes resolve.
- **Drainage area per sample.** The face area is on pass 1's grid (the cell is the sample); at the finest levels the 9 x 9 texels of a tile are far denser than the grid, so the bilinear read is smooth and the patch break-up (REND-055, `ground.patch`) supplies the small-scale variety.
- **The erosion depth** (removed, `max(0, deposited - change)`) needs kind 13 as well as kind 15 in the reader; decision 1 uses the deposited depth alone, the erosion depth comes with the second block of the D1 branch.
