### Open risks
- **Measurement launcher:** the planner session's runs are about 1.4x slower per thread than the native-UI coder session's, cause unproven (owner, 2026-10-16: perf windows run from a native-UI session on the planner's authorization). The calibration check guards every window.
- **Machine load:** the readiness gate refused two scenes for background CPU load. Shared sessions on Rasierklinge make windows fragile; the harness should log system-wide load during a run (queued).
- **Thin margins:** dive calibration 49.4 ms against 50; dive worst-frame lag 2.74 against 3; the top altitude band carries most of the lag (about 1.3 levels from 20,000 to 2,000 km).
- **Cold start:** dive-cold lag 1.77 levels and a 48 ms frame 2; a world without its pre-fill starts blurry. The pre-fill is part of the bake step.
- **WARP parallel crash** (test-only, gpu_skeleton and gpu_warmup): tracked; an exploration by sonnet-spikes follows.

### Learnings
- Tier-A fakes missed a real configuration cap (8 tiles in flight): an order-of-magnitude tier-B perf smoke is queued (owner, 2026-10-16).
- Each perf window uncovered the next layer: harness validity, scheduler cost, dispatch cap, upload ranking, worker contention, and finally the measuring session itself. A calibration kernel in every log turned out to be the decisive diagnostic.
- Pre-filling coarse levels 0-4 (25 MB, about 70 s) removed most of the high-altitude lag; tile generation cost is CPU-bound (hyperthreads and E-cores), not cache-bound.
