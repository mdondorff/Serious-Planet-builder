# 0051 Ocean channel, liquid table and the water-level field: implementation readings of ADR 0041
Status: proposed (sonnet-explorer, 2026-10-17, from the change `ocean-bake-and-water-level`; point 1 amends ADR 0041 point 3 and needs the planner's acceptance, the rest are readings the change already builds on)
Date: 2026-10-17
Source: ADR 0041 points 1 to 3 and 7; SPIKE-08; ADR 0026, 0027, 0035, 0042 point 6, 0049; the owner's M5 constraints 1 to 3 and 5; the numerics and spec reviews of the change

## Context
ADR 0041 fixes the ocean channel's algorithm (tiled union-find per bake block, an area threshold as body data), the field W with a body id and a kind, and says liquid kinds are world data whose appearance is look data. Building it needed decisions the text leaves open, and one place where two accepted sources pull apart: the owner's constraint 3 puts a parameter table with colour, emission, viscosity and waves in the world definition, while ADR 0041 point 3 and ADR 0042 point 6 put appearance in the look file.

## Decision
1. **The liquid table is world data with the physical parameters; presentation overrides are look data** (amends ADR 0041 point 3). A row has nine floats: colour in deep water, emitted radiance, viscosity, wave amplitude and wavelength (`liquid.<k>.*`, WDEF-006). They are what a generator, a CPU system or the HDR emission reads; the look file (ADR 0042 point 6) may override how a liquid is presented (absorption, roughness, foam, wave shaping) without changing the definition. A world that defines no row has the Earth table (water, id 0), so the definition hash of a world that never mentions liquids is unchanged; a world that defines any has exactly its rows. The sea of a body is three optional nodes with Earth defaults (`body.<n>.sea.level_m`, `.liquid`, `.min_area_fraction`). Definition schema version 2, identity migration from 1 (only keys were added).
   Consequences, stated honestly: the owner's table is kept, so three of the four items ADR 0041 point 3 lists as look data (colour, emission, waves) are definition nodes; they are **presentation parameters** (ADR 0035; bound: exact, validated ranges), not fields, and editing one changes the definition hash (the CON-09 cost: authored content records the base hash it was made against, ADR 0007). Precedence: where the look file sets a liquid's presentation it wins, for display only; no look section for liquids exists yet (`liquid_appearance` is named in `look/file.rs` only). The sea's liquid must name a row of the table (checked when the bake is opened). The sea's nodes are read from the definition directly by the bake, outside the recording context, like the radius (CON-06 exception with precedent): the one number the channel depends on, the area threshold, is an output parameter of the ocean block key, so a change of it re-keys exactly the channel.
2. **The ocean channel is its own record kind** (`Kind::GlobalOcean` = 4), one bit per vertex per block, LZ4, keyed by the tile, `B`, `res`, the bake's stage key and the area threshold. The stage key and the sample blocks' keys do not depend on the sea, so changing the threshold adds a channel without baking again. The answer is known only after every block has been seen, which is why the channel cannot live in the sample blocks (they are written first and the pack is append-only).
3. **Area is fixed point at 2^-48 of the unit sphere**, per vertex copy the solid angle of its dual cell clipped to its face; every copy of a node counts, so the faces sum to the sphere; a block owns the vertices it does not share with the next block (the last block of a row owns the far border). Integer sums make the table independent of the order and the number of threads. The threshold is `fraction * 4 pi 2^48` truncated.
4. **The sea's body id is one constant** (`WaterBodyId::SEA` = 1): every ocean component of a body shares its level and liquid. Ids with the top bit set are reserved for ids derived from component labels (hydrology's lakes). The label (smallest node id) is in the table and is the component's identity.
5. **The fine-point rule uses the lower corner always** and the other three vertices only when their axis weight is not zero (ADR 0041 point 1, "the stored vertex itself at weight 0"). A point between an ocean vertex and a land wall vertex is wet (the ocean vertex carries weight); a point between the wall and a dry basin vertex is dry although its continentalness is at or below sea level.
6. **Per-tile storage of W is not decided here.** The water pass (item 7) needs the water class per vertex of the water tiles; the options are a bit plane in the compact tile's reserved bits (a `MESH_VERSION` bump and a re-check of ADR 0033's slot pins), a CPU query per water tile at plan time (no storage, a cost per tile), or a tile-local mask sent with the water tile. The field is queryable by direction today and nothing stored depends on it. Item 7 decides with its measurements.
7. **`GLOBAL_VERSION` 4** carries the channel. Every mesh key moves through the climate version word (ADR 0049 point 3), so stored bakes, pre-filled packs and tiles are unreachable and are written again (item 8 regenerates the 16384 store); `MESH_VERSION` stays 7.

8. **The coast is defined by continentalness alone.** The sea producer's `level_m` is the surface height of water that exists where the bake says sea and the ocean flag says ocean; it does not move the coast. M5 seas are at 0; a sea level other than 0 is allowed as data and item 7 decides how the water pass treats land below it.

## Consequences
- Schema 2 ships under this proposal; the decision is reversible (no authored files exist, nothing but tests consumes schema 2 rows).
- The water pass reads a ready channel and a ready field; hydrology adds producers.
- A world that sets the sea nodes or a table has a different definition hash from one that does not, as for any node.
- The ocean cost at 1024 cells measured ad hoc: see the change's log line.

## Licences of adopted code or techniques
None. Union-find with path halving and the solid-angle formula of a rectangle of the tangent plane are textbook techniques.
