# 0026 Global-coarse field representation and bake layout
Status: accepted in part, points 1, 2, 3, 4, 6 and 7 (owner's delegation of 2026-10-12: the architect accepts ADRs that reviewers find sound and unambiguous; accepted by opus-planner after the spec-guardian and numerics reviews and their text fixes); point 5 (how regional fields read the bake) stays open for a new ADR before the first regional field reads the bake
Date: 2026-10-12
Source: m3-global-fields (GEN-013, GEN-014, #74), written by sonnet-explorer; spec-guardian and numerics reviews of it and of the architect's acceptance; ADR 0006, ADR 0018, ADR 0019, ADR 0022, ADR 0023 points 7 and 10, ADR 0024, ADR 0025 point 3; constitution CON-06, CON-07, CON-08, CON-14, CON-20, CON-21, CON-23; architecture report §5 and the M3 row

## Context
M3 needs a global-coarse bake (continents, elevation, climate) that regional fields later read, a persistent form of it, and a 1 km bake in under ten minutes. m3-global-fields built the field and an in-memory bake. The choices below fix what is stored and how it is keyed; they are cheap to change until the first bake is persisted (the next change) and regional fields read it.

## Decision
1. **One field, four channels.** Continentalness, elevation, temperature and precipitation are one field `global-coarse` with one version (`GLOBAL_VERSION`) and one implementation id (`cpu-global-coarse-v1`). Under ADR 0022 option 1 (GEN-007: a field reads only fields of earlier stages, never of its own) the channels cannot be separate global fields while they feed each other. Splitting them per channel needs ADR 0022 option 2 and the owner's CON-08 reading.
2. **Grid.** Vertex-centred, `(res + 1)^2` samples per cube face with the edge samples stored on both faces (equal bits, GEN-013), `res` (cells per face edge) a power of two, at the directions `TileId::sample_direction` gives for a level-0 tile under the body's face mapping. A bake with `res` above the in-memory limit is stored as blocks: block `b` is the level-`L` tile `b` with `L = log2(res / B)`, `B` the cells per block edge (a power of two, at most the codec's limit), holding its `(B + 1)^2` lattice samples, so block edges are duplicated with equal bits like face edges (the numerics review checked bit equality of a level-3 block against the level-0 lattice at `res` 16384). Every persisted bake is stored as blocks; at or below the limit `B = res` and `L = 0`. `B` is an output parameter of each block's content key (point 6).
3. **Channels.** `f32` each: continentalness (within -1.7 to 1.7, dimensionless), elevation in metres above the reference surface (clamped to -9000 to 9000, continuous across the coast), mean annual temperature in degrees Celsius, mean annual precipitation in millimetres (0 to 4500). At a stored vertex, land is a strict `>` of the stored `f32` continentalness against `SEA_LEVEL_C`, and `SEA_LEVEL_C` is a value exactly representable in `f32` (for example `0.1f32`, bits `0x3dcccccd`, widened to `f64`), so a comparison in `f32` (a shader) and one in `f64` agree. The sea level is part of the contract: moving it is a `GLOBAL_VERSION` bump. Which channel decides land *between* vertices (after interpolation) is part of point 5.
4. **What "1 km" means.** At Earth's radius a face edge is about 10,000 km, so 8192 cells are 1.2 km and 16384 are 0.6 km. The M3 criterion ("global 1 km bake <= 10 min") is read strictly, as no cell coarser than 1 km: 16384 cells per face edge (6 x 16385^2 = 1.6 G samples), baked as blocks and never held whole (6 x 16385^2 x 16 B is 26 GB). The background report sizes "1 km" as about 5e8 samples, which matches 8192 (4.0e8 samples, about 1.1 km by area); if 16384 misses ten minutes, relaxing to 8192 changes an M3 exit criterion and is the owner's decision. Cost per sample: estimated 4 us per core, measured ad hoc at about 1.2 us single-threaded with poor scaling across threads (not under the perf harness); GEN-014 holds the clause (tier C, measured by the architect).
5. **Reading (open).** How regional fields read the bake is not decided here. The ADR that decides it, before the first regional field reads the bake, must fix: the lattice position from integer tile indices (exact dyadic weights), never from inverting a direction; an interpolation formula that gives equal bits for a sample on a face edge read from either face (the shared edge runs in opposite directions on the two faces, so `a + (b - a) w` is not symmetric; `a (1 - w) + b w` with exact dyadic `w` is), with pinned known answers; how halo samples beyond a face edge are obtained (the bake stores nothing beyond the face edge); which channel decides land after interpolation (elevation is nonlinear in continentalness near the coast, so interpolated continentalness and interpolated elevation can disagree); and how the bake's key enters a reader's key (preferably once, as the one upstream key of a `Scope::Global` output, so that ADR 0022's "one key per input field" and GEN-007 stand; per-block upstream keys would amend ADR 0022 and need a new scope kind).
6. **Keys.** The bake has one persistent 128-bit stage key (STRM-011, `planet_cache::stage_key`, built in m3-stage-keys; ADR 0023 point 10) under its own format tag (1) and BLAKE3 context `planet-builder stage key v1`: a separate format beside the height and mesh keys of ADR 0018, not a new kind inside it, so the key spaces are domain-separated by the context. It covers everything GEN-007 lists for a global output, with `Scope::Global`, the field version `GLOBAL_VERSION`, `res` as cells per face edge in the resolution slot, and the hash version (the lattice noise comes from `planet_core::hash`). The bytes, all integers little endian, strings as `u32 length | UTF-8`: `tag (u8 = 1) | hash version (u32) | field version (u32) | stage tag (u8: 0 global-coarse, 1 regional, 2 local) | field id | implementation id | halo (f64 bits, -0.0 as 0.0) | scope (u8: 0 and 8 zero bytes for the whole body; 1 and the tile's raw id u64) | body id (u32) | body parameter hash (16 bytes) | face-mapping id | resolution (u32) | read count (u32) | the reads (node entries `0x01 | path | 16-byte hash` by path, then query entries `0x02 | kind | u32 parameter length | parameters | 16-byte result hash` by kind and parameters, duplicates collapsed) | input count (u32) | per input, by field id: field id | 16-byte key of its output`. The seed enters through the read set and the body parameter hash; `bake` takes any `FaceMapping`, and `grid_hash` does not cover its id, so the mapping id is in every key. Each stored block is a pack record of kind 3 whose content key is the ADR 0018 key with kind 3, the block's `TileId`, the bake's stage key as its source key, output parameter tag 1 = `B` (cells per block edge, which is the tile edge: ADR 0023 point 7) and `res` under a new tag reserved by the persisting change, the other ADR 0018 fields as in the bake key (generator version `GLOBAL_VERSION`, implementation id, face-mapping id, body id, body parameter hash) and an empty read set (the source key covers it); two blocks of one bake have different keys. Blocks are therefore not a stage scope: a reader lists the bake's one stage key as its upstream key (point 5), and no block scope or several keys per input field are needed. The face-mapping id is in every key: the bake takes any face mapping, and the test hash `grid_hash` does not cover it, so `grid_hash` is never a key.
7. **Reads through a context.** `global::sample(seed, d)` takes a seed. Before a bake is keyed, and before any regional field reads it, a generator wrapper gets the seed through `GenContext` per body (CON-06), with a contract test that generation under a recording context reads only what it declared (ADR 0021 point 7).

## Consequences
- The persistent form is a new record kind 3 in the tile store (ADR 0019/0024 packs; kind 3 is unused, so this does not amend them): payload codec like STRM-009 (shuffled `f32` planes, LZ4). Its node set id is ADR 0025 point 3's construction over the body's seed node path only (`world.seed` for body 0, `derived.body.N.seed` otherwise; no radius node, the field does not read the radius), with a pinned known answer (like STRM-010). The payload layout (channel order, plane order, codec version, limit on `B`) is fixed in a STRM requirement before the first bake is persisted.
- A change of any formula is a `GLOBAL_VERSION` bump and new known answers (tier A; the test asserts the recorded version).
- Code follow-ups (m3-global-fields, #74): `SEA_LEVEL_C` is `0.10` in `f64` today, which is not an `f32` value (`0.1f32` is above it), so a stored continentalness of exactly `0.1f32` is land in the bake and sea in an `f32` reader; make it `f32`-exact (a `GLOBAL_VERSION` bump with new known answers) with a test at that value. The doc comment on `GlobalSample::continent` says "about [-1, 1]"; the bound is 1.7. Add tier-A checks of edge-direction uniqueness and of a level-`L` block against the level-0 lattice at a production `res` (today only `res` 8 and level 0 are tested). GEN-014's memory clause should name the budget (CON-21) and can be tested at tier A by counting resident blocks; only the ten-minute clause needs tier C.
