# 0024 Clarifications to the tile pack format (ADR 0019)
Status: accepted (owner's delegation of 2026-10-12: the architect accepts ADRs that reviewers find sound and unambiguous; accepted by opus-planner after the spec-guardian and numerics reviews and their text fixes)
Date: 2026-10-11
Source: implementing ADR 0019 (STRM-008, `planet_cache::pack`) and its review; ADR 0019 (accepted, never edited: CON-23), ADR 0018, ADR 0023; constitution CON-05, CON-14, CON-22

## Context
ADR 0019 is accepted and fixes the pack as an append-only data file with a rebuildable Hilbert-ordered index. Implementing it, and reviewing the implementation, showed places where the text is incomplete, ambiguous or where the platform forced a choice. Most points are what a second reader (a remote server, a verifier, a compactor) needs. Some go beyond ADR 0019's text; under CON-23 this ADR **amends ADR 0019 in part** where listed under "Amends ADR 0019" below, and ADR 0019 is otherwise unchanged. Nothing is stored in this format yet outside tests, so every point can still change.

## Clarifications (what the code does; the owner may amend)
1. **The record carries its tile id and a header CRC.** ADR 0019's record has no tile, yet the index must be rebuildable from the data file alone and its sort key `(kind, face, level, Hilbert)` needs the tile. The record is `key (16) | kind (u8) | tile id (u64 LE) | generator version (u32) | hash version (u32) | node set id (16) | payload length (u32) | payload CRC-32C (u32) | header CRC-32C (u32) | payload`: a 61-byte header. The header CRC covers the 57 bytes before it. Without it, a zero-filled tail (which some file systems leave after a crash) decodes as valid empty records (`TileId` 0 is a real tile and the CRC-32C of nothing is 0), and a bit flip in the key, kind, tile or versions goes unnoticed. A header whose tile id is not a valid `TileId` is treated as a header that fails its CRC. This is pack format version 2; version 1 was never stored.
2. **Pack header** (24 bytes): magic `PLNTPACK`, format version (u32), hash version (u32), body id (u32), 4 reserved zero bytes.
3. **Hash version and body.** A pack made under another hash version is dead (ADR 0018: a hash version bump invalidates every entry): readers skip it, the writer leaves it alone and starts a new pack, and compaction (later) deletes it. A pack of another body is an error naming the file, because mixing bodies in one directory is a mistake, not a version change.
4. **Cache degrades, never refuses.** A pack shorter than its header (still being created, or cut by a crash before its first record) is empty to readers and is re-initialised by the writer; a pack with a bad magic or format version is skipped by readers and listed in `TileStore::problems()`, and is an error for a writer (which never overwrites it). Only canonical file names count: `pack-` plus the decimal sequence number zero-padded to at least eight digits (a u32 can need ten) plus `.tpack`. An unexpected end of file while scanning (a writer truncating a torn tail at the same moment) is a torn tail at that position for a reader, not an error that fails the store.
5. **Index file** (`.tidx`): a 40-byte header (magic `PLNTTIDX`, format version (the pack format version), 4 reserved bytes, data length (u64), tail CRC (u32), 4 reserved bytes, entry count (u64)), then entries of 40 bytes: sort key (11) | key (16) | record offset (u64) | payload length (u32) | one reserved zero byte. ADR 0019 estimates 48 bytes per entry; 11 + 16 + 8 + 4 is 39, so 40 is the 8-byte-aligned size and 6 million tiles are about 240 MB. **The sort key is `kind (u8) | face (u8) | level (u8) | Hilbert index (u64 big endian)`**: the one exception to ADR 0019's little-endian rule, so that comparing the bytes compares the numbers. The Hilbert curve's orientation is pinned by the known answers in `cache`'s tests. Reserved bytes are written as zero and ignored by readers.
6. **Staleness and hostile indexes.** An index is trusted only if its recorded data length equals the file length, its recorded tail CRC equals the CRC-32C of the data bytes `[max(length - 4096, 24), length)` (the pack header is never in the window), its entries are strictly increasing in `(sort key, key)` (so no index can list one key twice in one pack), and every entry names a record entirely inside the data. Anything else (missing, wrong magic or size, a count whose size arithmetic overflows) is rebuilt by one scan. Readers rebuild in memory and never write; the writer writes the index atomically (temp file and rename, retried a few times because a scanner can briefly hold the target on Windows) when it finishes a pack, at rollover, when it is dropped and on request. A writer whose index is current does not scan.
7. **Damage.** The scan checks payloads by streaming, never by holding them. A record that is cut short, or a zero-filled remainder, is a *torn tail*: the writer truncates it, readers ignore it. A complete record whose payload fails its CRC is *skipped*: the records after it stay readable, and a writer cuts nothing. A header that fails its CRC with non-zero data after it cannot be skipped (its length is not trusted): a scan stops there and reports it (a reader whose index is current does not scan and so keeps serving the records the index names), and the writer leaves the pack byte for byte as it is and continues in a new one. A read error during a scan is an error, never a torn tail. Damage in the middle of a pack that is larger than the 4096-byte tail window and whose index is current is not seen by the index check; it surfaces as a CRC failure on read of that record only (`PackError::Corrupt`, naming file, offset and key), which the caller treats as a miss, regenerates and logs. As ADR 0019 says, the entry is then dropped from the in-RAM index, so a long-lived store regenerates that tile once instead of returning `Corrupt` again (the code still keeps the entry: a follow-up).
8. **Duplicates.** Within a pack the later offset wins (earlier entries of an equal `(sort key, key)` are dropped from the index); across packs the pack with the higher sequence number wins; a corrupt newest copy is a miss even if an older pack holds an intact one.
9. **Size limit.** A record that would take a pack past the limit (4 GiB by default) first rolls the pack over, unless the pack holds no record yet, so a pack is at most the limit unless a single record is larger. A rollover that would need sequence number 2^32 is an error (`NoRoom`), never a wrap.
10. **Lock.** One writer per *directory*, not per pack: `File::try_lock` on `writer.lock` (`LockFileEx` / `flock`), taken before the packs are listed and held across rollovers, so two writers can never be active in one directory. The Windows lock is mandatory, so no other process can read the locked file; the holder's pid and the time the lock was taken (not the process start time, which std does not give) are written to `writer.holder` for the message a refused writer shows, and removed when the writer ends. A stale lock or holder file left by a crashed writer blocks nothing: the lock is the OS's, not the file's (tested with a real killed child process).
11. **Not built yet:** compaction, the size cap and LRU eviction, paging the index in blocks, an in-process writer thread, logging, the streamer using the store (it must reach it through an injected interface so the dive test can run with fake I/O, CON-04), mesh verification, and a check at append time that a record's hash version equals its store's (verify checks it).
12. **Height tile payload** (STRM-009): `codec version (u8 = 1) | samples per edge (u32 LE) | raw length (u32 LE) | LZ4 block` of the `(res + 1)^2` heights as little-endian `f32` shuffled by byte index (all first bytes, then all second bytes, and so on). The encoder refuses a resolution the decoder would refuse. Tiles are compared on decoded `f32` bits, not on compressed bytes: ADR 0019 says `cache-verify` "compares bytes", and the pack bytes are explicitly not deterministic, so bitwise equality of the decoded heights (exact for NaN payloads and signed zeros, unlike `==`) is the reading.
13. **Node set id** (the record field ADR 0019 introduces for compaction): `BLAKE3 derive_key("planet-builder node set v1")` first 16 bytes over the sorted, deduplicated paths of the field's reads (u32 length prefix, UTF-8) and of the body's radius node (`body.0.radius_m`, which is a body parameter and not in the read set). It is per *world*, from the field-wide reads; a field that reads cells gets per-tile query paths in its keys but not in this id. Compaction decides liveness with it, so it must become per tile before cell-reading fields are stored.
14. **What `cache-verify` finds.** An entry is *stale* when its key is no longer the definition's key: *explained* when its generator version, hash version or node set id differ from the current ones, *without a known reason* when they are all equal (a node value changed, which ADR 0019 calls reclaimable only by LRU, or the key function drifted). A run that compared nothing, because every entry is stale, fails unless the caller passes `--allow-stale`. An entry under the current key must carry the current metadata and equal its regeneration; a record that does not was written wrongly or has an input missing from its key. Regenerating from the same definition and generator finds nondeterminism, damage and wrongly written records; it finds an input missing from a key only when that input's value differs between building and verifying. Only body 0 is stored and verified. No `fsync` is done: every index is checked against the data and rebuilt when stale, and every payload against its CRC.

## Amends ADR 0019 (in part, CON-23)
- The record gains the tile id and a header CRC (point 1); ADR 0019's record list did not have them, and the rebuildable index needs the tile.
- One writer per directory instead of one per pack (point 10): two writers in one directory cannot pick sequence numbers safely, so the editor and `generate` use different directories or take the lock in turn.
- The holder's pid and lock time go to a separate `writer.holder` file instead of the lock file recording the process start time (point 10: the Windows lock is mandatory, so a refused writer cannot read the lock file, and std does not give the process start time).
- The sort key's Hilbert index is big endian (point 5).
- The 48-byte index entry of ADR 0019 was an estimate; 40 bytes is not a change of decision.

## Decision
Accepted as the reading of ADR 0019 and as the partial amendment listed above. A different reading later bumps the pack format version (nothing outside tests is stored). Code follow-ups: index entries strictly increasing in `(sort key, key)` (point 6), a payload CRC failure drops the entry from the in-RAM index (point 7), and end of file during a reader's scan is a torn tail (point 4).

## Consequences
- A second implementation can read and write the same files from ADR 0019 and this ADR.
- One damaged byte costs one tile (or, in a damaged header, the rest of one pack until compaction rewrites it); a process crash costs at most the record being written. Because nothing is `fsync`ed, an OS crash or power loss can lose every record not yet written back, and a header half on a saved page and half on a lost one reads as damage, not a torn tail: the writer then leaves that pack and starts a new one, and nothing wrong is ever served (the CRCs); a hash version bump costs nothing but disk space until compaction.
- The directory lock means the editor and the headless `generate` mode cannot write to one directory at the same time; they use different directories or take the lock in turn, as ADR 0019 already says.
