# SPIKE-37: domain cohesion review (cohesion)

Method: line counts from `wc -l` over `crates/*/src` and `crates/*/tests` (tests inside `#[cfg(test)]` modules of `src` files are counted in the source column); responsibilities from `lib.rs` docs, module lists and public items; dependencies from `Cargo.toml`; duplicates by grep over non-test code (a function of the same name or the same expression in more than one crate, then read). Everything below is a fact at `file:line` unless marked **reading** (my judgement) or **not checked**. Verdicts are the planner's.

## Summary (details below)
1. **The dependency order of CON-02 holds**, and no GPU crate is in the tree of core, world-def, generators, cache, streaming or frame. One exception to the intent: `editor` depends on `planet-render` (and so on wgpu) and uses nothing from it in `src` or `tests`.
2. **The field chain has two homes and a third is coming**: the base field is chosen in `generators` (`height_fields.rs:85`), the stamp stages and the water bound are added in `app` (`worldfield.rs:661-700`), and the owner's bake, ocean, floor and summary sources, counters and the tile pack are one 843-line `app` struct (`WorldTerrain`, `worldfield.rs:163`). A block field has to be added at the same seam.
3. **Eight domain concepts are written in several places** (table below); the largest are the angle between two directions (18 inline copies in 3 crates and one named function in `world-def`; `core` has none), the Earth radius (5 constants and 3 literals), lat/lon construction (12 sites, `core` has none), item reach (5 homes) and the level constants (constants in 7 crates, the prefill depth 4 in 3).
4. **Streaming has three homes** (`cache` holds the store, `streaming` the scheduler, `frame` the managed loop, the pool and the residency): tests of `frame` cite STRM-xxx 101 times, `cache` 146, `streaming` 99.
5. **`app` is two crates and a harness**: 5,500 of its 16,600 source lines are perf and stress scenes, 6,700 are the window and editor glue (including `EditRuntime`, an editor state machine of about 850 lines), the rest is run modes, the walking skeleton and the world of a run.
6. **Four crate docs are stale** (`frame`, `render`, `app`, `generators` still describe M0 and M1), and `render` holds 649 lines of spike code behind a feature (`spike_detail.rs`).

## 3. Leaks
### 3.1 Decisions that belong in a GPU-free crate (CON-03)
No decision about *what* to draw (selection, LOD, morph) was found in `render`; its modules are executors, and the one decision-like function is `read_exposure` (`lit.rs:633`, a read-back of the GPU's adaptation state). What was found:
| Where | What | Fact |
|---|---|---|

| `render/lit.rs:633` | exposure adaptation runs on the GPU and is read back; the CPU side computes only the pre-exposure (`frame::look::pre_exposure_factor_with`) | by design (REND/LOOK), listed because M8's pop fade will need the same pattern |
